# بيان — BAYAN

### المساعد المؤسسي الذكي للجامعات العربية

اسأل عن بيانات جامعتك بالعربية — يحوّل سؤالك إلى SQL آمن، يسترجع السياسات واللوائح، يحلل ويرسم، ويجيبك في ثوانٍ.

**مساعد ذكاء اصطناعي مؤسسي يعتمد معمارية وكلاء متعددين (LangGraph) فوق نظام ERP جامعي حقيقي (Odoo + OpenEduCat)**

## نظرة عامة

**بيان** هو مشروع تخرج يبني مساعداً ذكياً مؤسسياً يُمكّن المستخدمين من التحدث بالعربية مع بيانات جامعتهم:

- **NL2SQL عربي**: تحويل الأسئلة العربية إلى استعلامات SQL آمنة تُنفَّذ للقراءة فقط فوق طبقة **Smart Views** مبسّطة
- **RAG**: استرجاع الإجابات من لوائح الجامعة وسياساتها وأنظمتها المعرفة
- **وكلاء متعددون**: Supervisor يوجّه السؤال بين وكلاء SQL / RAG / المحلل / المُعدّ — عبر LangGraph
- **إجابات غنية**: نص عربي + جداول نتائج + رسوم بيانية + تقارير قابلة للتصدير

المرجع الأساسي للمشروع هي **وثيقة مشروع التخرج** (مستودع Bayan-Documentation).

## هيكل المستودع

```
Bayan/
├── backend/            # FastAPI + وكلاء LangGraph + مصنع LLM موحد
│   └── app/
│       ├── agents/     # الوكلاء الخمسة: supervisor, sql, rag, analyst, reporter
│       ├── api/        # نقاط النهاية REST + البث SSE (v1)
│       ├── core/       # الإعدادات والسجلات + عقد أحداث SSE
│       ├── db/         # اتصالات قواعد البيانات
│       ├── llm/        # مصنع النماذج بالأدوار + مزوّد mock
│       ├── schemas/    # مخططات Pydantic (عقود مشتركة)
│       └── static/     # واجهة الاختبار الموحدة (playground.html)
├── frontend/           # Next.js — واجهة محادثة عربية RTL
├── database/
│   ├── smart_views/    # طبقة المشاهد المبسطة فوق مخطط Odoo (ابتكار المشروع)
│   └── university_demo/  # القاعدة التجريبية الموحدة (schema + seed + reader + تحقق)
├── evaluation/         # مجموعة Golden Dataset + عدّادات القياس (هدف دقة 90%)
├── docs/               # التوثيق الهندسي + سجل القرارات المعمارية (adr/)
├── scripts/            # سكربتات الإعداد والفحص
├── infra/              # تهيئة النشر (لاحقاً: Nginx + مراقبة)
└── .github/workflows/  # CI: فحص + اختبارات + قاعدة حية + نظافة عند كل PR
```

## البدء السريع

### المتطلبات
- Docker + Docker Compose
- Python 3.11+ (للتطوير المحلي للـ backend)
- Node.js 20+ (للتطوير المحلي للـ frontend)

### التشغيل

```bash
git clone https://github.com/GP-Project-ust/Bayan.git
cd Bayan
cp .env.example .env        # الافتراضي mock — يعمل بلا أي اتصال خارجي

# البنية التحتية فقط (قاعدة المنصة + كاش + متجهات):
make infra

# قاعدة الجامعة التجريبية الموحدة (بيانات اصطناعية عربية حتمية):
make dev-db

# تشغيل الخلفية محلياً:
make backend-dev
```

| الخدمة | العنوان |
|--------|---------|
| **واجهة الاختبار الموحدة (لكل الفريق)** | http://localhost:8000/dev/playground |
| واجهة API (توثيق تفاعلي) | http://localhost:8000/docs |
| فحص الصحة | http://localhost:8000/api/v1/health |

### واجهة الاختبار الموحدة `/dev/playground`

صفحة واحدة (HTML/CSS/JS خالص بلا بناء) تتيح لكل عضو اختبار السلسلة
كاملة من المتصفح: سؤال عربي ← توجيه Supervisor ← بطاقة لكل وكيل
(SQL المعروض + عدد الصفوف + المدة) ← الإجابة النهائية، مع أمثلة جاهزة
وعرض الأحداث الخام. تعمل بوضع mock من دون أي نموذج أو مفاتيح.

### تبديل النموذج (سطر واحد)

```bash
# .env
LLM_PROVIDER=mock      # افتراضي: ردود حتمية بلا اتصال
# LLM_PROVIDER=ollama  # محلي — بعد: make llm
# LLM_PROVIDER=openai  # سحابي — يتطلب تثبيت langchain-openai
```
الأدوار مضبوطة مسبقاً داخل `app/llm/provider.py` (درجة حرارة مناسبة لكل وكيل).

### بيئة الاختبار (قاعدة بيانات الجامعة)

**الطريق الموصى به لكل الفريق:** القاعدة التجريبية الموحدة — `make dev-db`
(قاعدة PostgreSQL خفيفة بأسماء جداول OpenEduCat نفسها + بيانات جامعية
عربية اصطناعية حتمية + دور قراءة فقط مختبر أمنياً — راجع
`database/university_demo/README.md` و ADR-001).

**خيار متقدم:** بيئة Odoo/OpenEduCat حقيقية ببيانات جامعة يمنية واقعية
(5000+ طالب) من مستودع
[openeducat-yemen-university](https://github.com/GP-Project-ust/openeducat-yemen-university) —
انظر `database/README.md` لطريقة ربطها ببيان بصلاحية قراءة فقط.
