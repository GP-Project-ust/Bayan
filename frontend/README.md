# بيان — Bayan Next.js UI (النسخة التراكمية حتى المراجعة النهائية)

مشروع واجهات عربية RTL متوافق مع هوية بيان المعتمدة، مع **نماذج تجريبية فقط** لم تُربط بـFastAPI أو PostgreSQL أو Qdrant أو LangGraph.

## الشاشة 35: إدارة مزودي النماذج اللغوية

- المسار: `/platform/models`.
- 6 مزودين افتراضيين و10 نماذج افتراضية للمعاينة.
- فلاتر حسب الاسم ونوع التشغيل وحالة المزود والمهمة.
- معلومات النماذج وحدود الاستخدام وفحص جاهزية **محلي لا يستخدم الشبكة**.
- مسودات تفعيل وحدود طلبات محفوظة محليًا فقط، دون تخزين أسرار.
- تصدير CSV للبيانات الوصفية، ودرج تفاصيل مزود ونموذج، وتجربة أدوار RBAC.
- الإعدادات الفعلية ومفاتيح API وصلاحيات الخادم **لم تنفذ بعد**.

### التشغيل

```bash
npm install
npm run check:model-providers
npm run lint
npm run build
npm run dev
```

ثم افتح `http://localhost:3000/platform/models`.

## الشاشة 36 — مراقبة صحة خدمات النظام

- المسار: `/platform/health` لمسؤول المنصة في نموذج الصلاحيات.
- 8 خدمات و11 تنبيهًا اصطناعيًا، مع البحث والتصفية والدرج الجانبي وفحص محلي دون اتصالات شبكة وتصدير CSV آمن.
- الوصول كذلك من صفحة `/platform/models` عبر رابط لوحة صحة الخدمات.
- كل الإشارات لحالة الخدمة أو آخر فحص أو تنبيه تُعرض بوصفها أمثلة تدريبية لا نتائج حية.
- اختبار الشاشة: `npm run check:system-health`؛ الفحوص التراكمية: `node --test tests/contracts/*.test.mjs`.
- ملفات الشاشة في `components/system-health/` و`lib/system-health/` والتوثيق `docs/SCREEN_36_SYSTEM_HEALTH.md`.
- البناء الفعلي `npm install && npm run build` واختبارات Playwright مطلوبان بعد تثبيت التبعيات.


## الشاشة 37 — مراقبة الوكلاء الذكيين

- المسار: `/platform/agents` لمسؤول المنصة في نموذج الصلاحيات.
- لوحة للوكلاء الخمسة `Supervisor` و`SQL` و`RAG` و`Analyst` و`Reporter`، مع البحث والتصفية وبطاقات التفاصيل ومقارنة نسب النجاح وتصدير CSV للبيانات الوصفية.
- الأرقام مشتقة من مجموعة التتبعات الاصطناعية الثمانية المضمنة؛ لا تمثل قياسات أداء حية.
- تتبع المؤسسة لا يظهر لمسؤول المنصة تلقائيًا؛ رابط تفاصيل التتبع مشروط بصلاحية `traces.view`.
- الوصول إلى الشاشة من لوحة صحة الخدمات `/platform/health`، كما تحتوي الشاشة على روابط لصحة الخدمات ومزودي النماذج.
- الاختبار: `npm run check:agent-monitoring`؛ الفحوص التراكمية: `node --test tests/contracts/*.test.mjs`.
- ملفات الشاشة: `components/agent-monitoring/` و`lib/agent-monitoring/`، والتوثيق `docs/SCREEN_37_AGENT_MONITORING.md`.
- لا يوجد اتصال حي بـLangGraph أو FastAPI أو قواعد البيانات. البناء الفعلي واختبارات Playwright مطلوبان بعد تثبيت التبعيات.

**التقدم:** 37 نموذج شاشة من 42 شاشة مخططة، مع 7 مراحل Design System. هذه ليست نسبة الجاهزية للإنتاج.


## الشاشة 38 — إعدادات المنصة

- المسار: `/platform/settings` لمسؤول المنصة وفق محاكاة `platform.manage`.
- أربعة أقسام: الإعدادات العامة واللغة والمنطقة الزمنية؛ مهلة SQL ومحاولات التصحيح وإعادة التنفيذ؛ الاحتفاظ بسجل التدقيق وإخفاء الحقول الحساسة؛ مزود النماذج الافتراضي وحدود الطلبات والتزامن.
- تحقق من النطاقات، ومراجعة الفروقات قبل الحفظ، وإلغاء المسودة، واستعادة النسخة السابقة كمسودة، وسجل تغييرات محلي، وتصدير JSON دون أسرار.
- الحفظ محلي في المتصفح فقط؛ لا توجد اتصالات API ولا تغييرات فعلية على إعدادات الخادم. لا تتضمن الواجهة حقول مفاتيح API أو كلمات مرور.
- الاختبار: `npm run check:platform-settings`؛ الفحوص التراكمية: `node --test tests/contracts/*.test.mjs`.
- الملفات: `components/platform-settings/` و`lib/platform-settings/`، والتوثيق `docs/SCREEN_38_PLATFORM_SETTINGS.md`، ومخطط التدفق `docs/flows/46-platform-settings-flow.{mmd,dot,png,svg}`.
- مسارات Backend المقترحة موثقة فقط وليست منفذة. يلزم فرض RBAC والتحقق وتسجيل التغييرات على الخادم.

**التقدم:** 38 نموذج شاشة من 42 شاشة مخططة، مع 7 مراحل Design System. هذه نسبة تغطية نماذج الواجهات وليست نسبة الجاهزية للإنتاج.
## المراجعة النهائية — المرحلة 42

- اكتملت مراجعة النسخة التراكمية بعد إضافة شاشة منع الوصول `/forbidden`، وشاشة الخدمة غير المتاحة `/unavailable`، وخريطة الواجهات `/screens`.
- يحتوي كتالوج النظام على 42 مسارًا فريدًا، وقد تمت مطابقة المسارات مع صفحات Next.js الثابتة أو المسار الديناميكي لتفاصيل المحادثة.
- تم ضبط `app/[...slug]/page.tsx` حتى لا يعيد توليد مسارات لها صفحات مخصصة، مع إبقاء فحص `notFound()` للمسارات غير المسجلة.
- تم تنفيذ مراجعة آلية للمسارات وبيانات الكتالوج، وإضافة `npm run check:final` لتشغيل مراجعة المسارات وجميع اختبارات العقود.
- تقرير التسليم: `docs/FINAL_PROJECT_AUDIT.md`، ومصفوفة المسارات: `docs/FINAL_ROUTE_MATRIX.md`.

### فحوص النسخة الحالية

- اختبارات العقود بعد إضافة فحوص المراجعة النهائية: **329 اختبارًا ناجحًا من 329**.
- لم يتم تشغيل `npm run build` أو اختبارات Playwright في بيئة إعداد الحزمة؛ لا توجد `node_modules` مثبتة، كما لم تتوفر حزم npm في الذاكرة المحلية لإنشاء ملف قفل دون اتصال. نفّذ `npm install` مع اتصال بسجل npm ثم `npm run lint` و`npm run build` و`npm run test:e2e` قبل اعتماد النشر.
- الواجهات الحالية نماذج Frontend تجريبية. لا يوجد اتصال حي بـFastAPI أو PostgreSQL أو Qdrant أو Redis أو Ollama أو LangGraph، ولا تعتبر أرقام المراقبة أو نتائج الفحص بيانات تشغيل حقيقية.
- يجب تنفيذ التفويض RBAC والتحقق من الصلاحيات وعزل المؤسسات وتسجيل التدقيق على الخادم قبل الإنتاج.
