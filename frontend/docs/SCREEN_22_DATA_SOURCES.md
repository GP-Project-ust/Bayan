# الشاشة 22 — إدارة مصادر البيانات | Bayan Data Sources Management

## المجال والمسار
- **المسار:** `/admin/data-sources`
- **حالة الاستخدام:** UC-05 — إدارة مصادر البيانات وتصنيفاتها الأمنية.
- **التقنيات:** Next.js App Router / React / TypeScript / CSS / RTL.
- **الهوية:** نفس النمط المعتمد من مشروع بيان السابق؛ CSS جديد بأسماء `bds-` مستقلة.
- **نطاق التنفيذ:** واجهة تفاعلية تجريبية **دون اتصال بالخادم**.

## المكونات
1. عنوان وأثر بصري من تصميم بيان مع إقرار بأن البيانات افتراضية.
2. مؤشر إجمالي مصادر البيانات، والحالة الجاهزة/التحذير، والمصادر المقيّدة والمحظورة.
3. جدول مصدر بيانات موحد: الاسم والنوع والجهة والحالة والتصنيف والإجراءات.
4. فلاتر البحث العربي والنوع والحالة والتصنيف، مع الترتيب وتقسيم الصفحات.
5. درج تفاصيل المصدر يعرض `example.invalid` بدل عناوين خدمات حقيقية، بلا أسماء دخول أو كلمات مرور.
6. **محاكاة** اتصال لا ترسل `fetch` أو `axios` أو طلبات شبكة؛ نتيجة محلية مشتقة من Fixture فقط.
7. نافذة تأكيد لتعطيل مصدر أو تنشيطه محليًا، مع منع العبث بالمصدر المحظور.
8. روابط إلى الشاشة 23 المستقبلية `/admin/data-sources/new`، ومعالجة رفض الصلاحية.

## الأدوار والصلاحيات
- `it_admin` يستطيع استعراض وظائف الإدارة لأن `sources.manage` موجودة في سياسة العرض المركزية.
- `employee` و`manager` و`platform_admin` ممنوعون من هذه الواجهة في المحاكاة، ولا يُعامل مسؤول المنصة كمسؤول عن بيانات أي مؤسسة تلقائيًا.
- **هذه ليست حماية كافية**؛ يجب فرض صلاحية الإدارة، ومحدد المؤسسة `tenant_id`، ومنع كشف الأسرار على FastAPI/قاعدة البيانات والخدمات المتصلة.

## البيانات التجريبية والأمن
- سجل المصادر **8 مصادر وهمية**؛ نطاقات `example.invalid` مستخدمة حتى لا توحي بمصدر فعلي.
- التصنيفات `public`، `masked`، `restricted`، `blocked` تمثل مستويات وصول لأغراض العرض، ولا تحل محل سياسة الأعمدة والسجلات والعروض الذكية.
- الحالات `connected`، `attention`، `pending`، `disabled` كلها توضيحية.
- مخزن `localStorage` يضم أعلام التعطيل فقط في المفتاح `bayan.demo.sources.status.v1`؛ لا تتخزن أسرار ولا بيانات شخصية أو رموز وصول.
- المصدر `SRC-007` محظور؛ لا يتاح اختباره أو تنشيطه من هذه الشاشة.

## العمل المتوقع في Backend لاحقًا (غير منفذ)
- `GET /api/data-sources` لعرض المصادر بحسب المؤسسة مع فلترة خادمية.
- `GET /api/data-sources/:id` للتفاصيل المصرّح بها، دون تسريب بيانات الاعتماد.
- `POST /api/data-sources/:id/test` لتنفيذ اختبار الاتصال من خدمة خادمية معزولة ومراقبة.
- `PATCH /api/data-sources/:id/status` لتعديل الحالة مع سياسات RBAC وسجل تدقيق.
- تخزين الأسرار في خدمة إدارة أسرار؛ حظر تسجيل بيانات الاعتماد أو إعادتها إلى المتصفح.
هذه مسارات **مقترحة** وليست API حقيقية موثقة من المشروع.

## تدفق الشاشة
المخطط: `docs/flows/30-data-sources-flow.mmd`، مع PNG وSVG. يبدأ من اختيار الدور، والتحقق من الصلاحية، وعرض القائمة، ثم البحث أو التفاصيل أو المحاكاة أو تغيير الحالة المحلية.

## الاختبارات
- `npm run check:data-sources`: فحص بنيوي وصياغة الملفات ومقارنة العناصر المرجعية مع الشاشة 21 واختبارات العقد.
- `node --test tests/contracts/*.test.mjs`: اختبارات العقود المتراكمة.
- `npm run lint && npm run build`: **يجب تشغيلهما بعد `npm install`**.
- `npm run test:e2e` بعد تثبيت Chromium عبر Playwright.

## معايير القبول
- عرض ثمانية مصادر خيالية من دون أسرار.
- عمل البحث والتصفية والترتيب والتصفح.
- منع دور غير مخوّل من رؤية قائمة المصادر.
- منع تمكين مصدر محظور حتى بعد تغيير الحالة محليًا.
- عرض نتائج فحص توضيحية لا تدعي اتصالًا حقيقيًا.
- بقاء شاشة المحادثة ولوحة الإدارة وCSS القديم كما هي.
- عدم اعتبار الفحص البنيوي بديلًا عن اختبار البناء والتطابق البصري في المتصفح.
