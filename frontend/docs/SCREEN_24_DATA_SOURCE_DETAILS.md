# الشاشة 24 — تفاصيل مصدر البيانات (Data Source Details)

**المشروع:** بيان (Bayan) · **المسار:** `/admin/data-sources/details?id=SRC-001` · **المجموعة:** إدارة مصادر البيانات (UC-05)

## الغرض
إتاحة مراجعة مصدر مؤسسي واحد من واجهة عربية RTL، مع أمثلة وصفية لحالة المصدر ونوعه والجهة المالكة، والجداول والحقول والتصنيفات الأمنية والعروض الذكية. هذه الصفحة نموذج واجهة فقط: لا يوجد اتصال بقاعدة بيانات أو اكتشاف حقيقي لمخطط PostgreSQL أو Odoo، ولا توجد أي بيانات اعتماد.

## الربط بالشاشات
- `/admin/data-sources`: زر **فتح الصفحة الكاملة** بجوار كل مصدر في القائمة.
- `/admin/data-sources/new`: المصادر الجديدة المحفوظة في `bayan.demo.sources.created.v1` تظهر في القائمة والتفاصيل بلا افتراض أي مخطط لها.
- `/admin/smart-views`: رابط إلى قسم إدارة العروض الذكية المخطط له (قد يفتح قالبًا تجريبيًا إلى حين بناء تلك الشاشة).

## الأقسام
1. بطاقة المصدر: العنوان والمعرّف والنوع والحالة والتصنيف واسم الجهة؛ مع حالة اختبار الاتصال التوضيحي.
2. مؤشرات وصفية: مجموعات مسجلة كبيانات افتراضية، عدد الجداول والحقول والعروض الممثلة في واجهة التدريب.
3. التبويبات: **نظرة عامة**، **الجداول والحقول**، **تصنيف الوصول**، **العروض الذكية**، **النشاط التوضيحي**.
4. فحص إعدادات الاتصال التوضيحي في نافذة منبثقة؛ لا يرسل طلبات شبكة.
5. نموذج مسودة مراجعة من قائمة أسباب ثابتة، مع حفظ محلي فقط وحذف المسودة بعد التأكيد.
6. حالات منع الوصول، مصدر غير موجود، معرّف غير صالح، مصدر محظور، مصدر أضيف محليًا بلا مخطط، وخطأ تخزين محلي.

## حدود الأمان
- التبويبات لا تعرض قيم صفوف أو بيانات أفراد أو كلمات مرور أو مفاتيح.
- المصدر المصنّف **محظور** لا يعرض حتى بيانات المخطط التمثيلي، ولا يسمح بمراجعة أو فحص توضيحي.
- الحقول المعلّمة `blocked` توضيحية، ويُحجب وصفها. عند تنفيذ النظام الحقيقي يجب منع أي وصول غير مصرح به في Backend.
- صلاحية `sources.manage` تجريبية في الواجهة (مسؤول تقنية المعلومات). مسؤول المنصة ليس مخولًا تلقائيًا لاطلاع على بيانات المؤسسة.
- لا تقبل الصفحة إدخال أسرار؛ تحفظ فقط سبب مسودة المراجعة من قائمة ثابتة مع المعرّف والوقت.
- كل بيانات `lib/data-sources/details.ts` عبارة عن **Fixtures** خيالية توضح التصميم، وليست Schema استُكشف من قاعدة بيانات.

## حالات الاستخدام والقبول
| الحالة | المتوقع |
|---|---|
| `/admin/data-sources/details?id=SRC-001` | تظهر بيانات ومخطط *توضيحي* للمصدر الأكاديمي |
| `/admin/data-sources/details?id=SRC-007` | مصدر محظور، بلا مخطط وبدون فحص اتصال أو مراجعة |
| `/admin/data-sources/details?id=SRC-999` | رسالة «لم يُعثر على المصدر» مع العودة |
| `/admin/data-sources/details?id=bad` | رسالة «معرّف مصدر غير صالح» |
| `/admin/data-sources/details` | مطالبة باختيار مصدر من القائمة |
| مصدر `SRC-DEMO-...` محلي | يظهر كصف محفوظ محليًا، بلا أي جداول أو عروض مخترعة |
| دور `platform_admin` | رسالة منع الوصول مع رابط العودة |
| إنشاء مسودة مراجعة | تخزين محلي في `bayan.demo.sources.reviews.v1` دون تحديث الصلاحيات أو المصدر |

## الاستعداد للربط مع FastAPI لاحقًا — اقتراحات وليست مسارات منفذة
- `GET /api/v1/data-sources/{id}`: مصدر حسب المؤسسة مع صلاحية محددة.
- `GET /api/v1/data-sources/{id}/schema`: بيانات وصفية مصرح بها فقط، مع إخفاء أسماء/أنواع الحقول المحظورة إن لزم.
- `GET /api/v1/data-sources/{id}/smart-views`: عروض ذكية قابلة للاستخدام لدى الدور المصرح به.
- `POST /api/v1/data-sources/{id}/health-check`: فحص عبر الخادم فقط مع مهلة وقيود وأثر تدقيق.
- `POST /api/v1/data-sources/{id}/review-requests`: طلب مراجعة موثق، مع حماية CSRF والتحقق من الهوية بحسب نظام المصادقة المختار.

يجب استخدام معرفات مؤسسة مضمّنة في سياق الهوية لا حقول يختارها المستدعي، وتطبيق RBAC في Backend وتسجيل طلبات المراجعة في Audit Log وإدارة الأسرار في مخزن آمن. المسارات أعلاه مقترحة ولم تُبنَ في هذا المشروع.
