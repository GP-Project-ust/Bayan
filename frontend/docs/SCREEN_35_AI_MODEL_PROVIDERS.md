# بيان — الشاشة 35: إدارة مزودي النماذج اللغوية

## الهدف والنطاق

**المسار:** `/platform/models`  
**الدور:** مسؤول المنصة (`platform.manage`) وفق محاكاة RBAC، مع ضرورة فرض الصلاحية الحقيقية على FastAPI.  
**المتطلب المرجعي:** FR-13 في كتالوج الشاشات المخطط.  
**الحالة:** واجهة تفاعلية تجريبية، لا تُشغّل نماذج AI ولا تتصل بمزود حقيقي.

## أقسام الواجهة

1. **لوحة مؤشرات:** عدد المزودين والنماذج وحالات الجاهزية الاصطناعية.
2. **البحث والمرشحات:** الاسم، النوع (محلي/سحابي/بوابة)، الحالة والمهمة.
3. **قائمة المزودين:** حالة وصفية، نوع التشغيل، النماذج المرتبطة، وصف حماية بيانات الاعتماد.
4. **جدول النماذج:** اسم النموذج، قدراته، نافذة السياق الرمزية، حد المخرجات وحد طلبات الدقيقة، تفعيل مسودة.
5. **درج التفاصيل:** بيانات وصفية للمزود ومعلومات النموذج بدون أسرار.
6. **فحص الجاهزية:** محاكاة حتمية لا تُطلق أي طلب شبكة ولا تقيس زمن الاستجابة.
7. **مسودات الإعدادات:** إمكانية حفظ `modelId, enabled, rpm` فقط في `localStorage`، مع رفض أي مفاتيح زائدة أو رقم غير صحيح أو RPM خارج 1–500.
8. **تصدير CSV:** بيانات وصفية تدريبية فقط، مع تعقيم بدايات الصيغ القابلة للتفسير في Excel.
9. **الحالات:** منع الوصول، عدم العثور على نتائج، أخطاء التحقق وفشل التخزين ورسائل النجاح.

## الحماية والخصوصية

- **لا توجد حقول لكلمات مرور أو API Keys.** لا تُخزن بيانات اعتماد أو عناوين تشغيل حقيقية داخل البيانات التدريبية.
- كل مزود ونموذج يحمل معرّفًا افتراضيًا (`PRV-DEMO-*` و`MDL-DEMO-*`).
- حالة «جاهز» تعني جاهز *في سيناريو العرض فقط*، وليست ادعاء بأن Ollama أو Azure OpenAI أو أي خدمة متصلة فعليًا.
- فحص الجاهزية لا يستخدم `fetch` أو WebSocket أو أي API خارجي. نتائجه مبنية على القيم الثابتة في `lib/model-providers/models.ts`.
- **صفر طلبات شبكة، وصفر عمليات استدلال، وصفر تعديلات Backend.**
- مصفوفة RBAC في المتصفح ليست حاجزًا أمنيًا. عند التكامل يجب تطبيق دور مسؤول المنصة داخل FastAPI، وتخزين الأسرار في مخزن أسرار على الخادم، وإضافة سجل تدقيق لكل تغيير، والتحقق من حدود الاستخدام الحقيقي.

## البيانات

- 6 مزودين افتراضيين، و10 نماذج افتراضية.
- حالات: جاهز توضيحيًا، محدود توضيحيًا، متوقف توضيحيًا، غير مهيأ.
- أدوار المستخدمين الأخرى تُمنع من عرض الصفحة في المحاكاة، ولا تمنح صلاحية الاطلاع على بيانات المستأجرين الداخلية.

## التحقق وتشغيل المشروع

```bash
npm install
npm run check:model-providers
npm run lint
npm run build
npm run dev
```

ثم افتح `http://localhost:3000/platform/models`.

الاختبارات البنيوية وعقود البيانات **لا تعوّض** اختبار البناء TypeScript الكامل، ولا اختبار التنقل والتجاوب البصري في متصفح حقيقي.

## واجهات Backend المقترحة لاحقًا — غير منفذة

- `GET /api/platform/model-providers` — معلومات تشغيلية وصفية، غير حساسة.
- `GET /api/platform/models` — قائمة النماذج وحدود الاستخدام المصرح بها.
- `PATCH /api/platform/models/{id}` — تغيير معتمد بعد تفويض مسؤول المنصة، مع تدقيق.
- `POST /api/platform/model-providers/{id}/health-check` — تحقق خادمي محكوم بالوقت والمعدل مع إرجاع حالة مقيدة.

هذه أسماء مسارات تصميمية مقترحة **وليست تأكيدًا بوجود API فعلي** في Backend الحالي.
