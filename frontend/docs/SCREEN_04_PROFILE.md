# الشاشة 04 — الملف الشخصي | Bayan

## الغرض
تقديم صفحة مستقلة على `/profile` لعرض بيانات الحساب والمؤسسة والدور، والسماح بتعديل بيانات غير إدارية على مستوى واجهة المستخدم، وتوضيح الصلاحيات وفق مصفوفة RBAC المعتمدة في نموذج Bayan.

**الحالة:** واجهة Frontend تجريبية؛ لا توجد جلسة مصادقة حقيقية أو API لحفظ الملف الشخصي.

## الأجزاء

| الجزء | الوظيفة |
|---|---|
| رأس الصفحة وبطاقة الهوية | الاسم المعروض والمسمى الوظيفي والمؤسسة والدور |
| نظرة عامة | الاسم الرسمي والبريد المؤسسي والقسم والهاتف والدور |
| البيانات الشخصية | تعديل الاسم المعروض والمسمى الوظيفي والهاتف، مع التحقق من الإدخال |
| الدور والصلاحيات | قائمة capabilities، مع إمكانية محاكاة دور آخر للعرض فقط |
| تفضيلات العرض | كثافة البطاقات وإشعارات البريد التجريبية |
| أمان الحساب | حالة 2FA والجلسات كوظائف غير متصلة، ورابط تدفق الاستعادة |
| نافذة تأكيد | تحذير قبل تجاهل التعديلات غير المحفوظة |

## سياسة الحقول
- **قراءة فقط:** الاسم الرسمي، البريد الإلكتروني، المؤسسة، القسم، والدور الحقيقي.
- **تعديل تجريبي:** الاسم المعروض (2–70 حرفًا)، المسمى الوظيفي (حتى 80 حرفًا)، الهاتف (اختياري، 7–15 رقمًا دوليًا).
- **الحفظ:** تحديث حالة React في الذاكرة مؤقتًا، دون `fetch`, `localStorage`, `sessionStorage` أو طلب API. تُمحى القيم عند تحديث الصفحة.
- **أدوار المعاينة:** `employee`, `manager`, `it_admin`, `platform_admin` من `lib/access/policy.ts`. يسمح اختيار الدور بتغيير طريقة عرض القائمة فقط ولا يغير وصول المستخدم للخادم.
- **البيانات التجريبية:** `ahmed@university.example` عنوان محجوز للأمثلة، و«جامعة بيان التجريبية» اسم افتراضي.

## الأمان والربط اللاحق
عندما تصبح خدمات المصادقة جاهزة، تُقرأ الهوية ودور المؤسسة من جلسة موثقة، وليس من حقل يختاره المستخدم. ويُقيَّد تعديل البيانات وفق صلاحيات الخادم، مع إعادة التحقق من المدخلات، وتسجيل تغييرات الحساب في التدقيق. لا تعرض UI رموز جلسات أو معلومات أمنية غير مثبتة.

### عقود API المقترحة (غير منفذة)
- `GET /api/v1/me` معلومات المستخدم الموثقة ومؤسسته والدور والقدرات.
- `PATCH /api/v1/me/profile` تحديث حقول الاسم المعروض/الهاتف/المسمى المسموحة.
- `GET /api/v1/me/sessions` عرض جلسات المستخدم الموثقة (عند دعمها).
- `DELETE /api/v1/me/sessions/{id}` إلغاء جلسة بعد المصادقة/التفويض.

هذه المسارات مقترحات تصميمية **وليست** تأكيدًا بوجودها في Backend الحالي.

## اختبار القبول
1. فتح `/profile` يعرض الهوية العربية وRTL وشارة «حساب للعرض فقط».
2. رابط الملف الشخصي في شريط الواجهتين ينتقل إلى `/profile` دون تعديل شكلهما الأساسي.
3. الحقول الإدارية ثابتة ولا يوجد زر لتعديل الدور الحقيقي أو البريد.
4. رفض الاسم ذي الحرف الواحد، والمسمى الأطول من 80 حرفًا، والهاتف غير الصالح.
5. حفظ البيانات الصحيحة يحدّث البطاقة والملخص ويعرض إشعارًا بأنه محلي فقط.
6. عند مغادرة نموذج معدل إلى تبويب آخر تظهر نافذة تأكيد؛ يمكن إلغاؤها أو تجاهل التغييرات.
7. تغيير دور المعاينة يعرض الصلاحيات المناسبة، دون أي طلب API.
8. عرض الهاتف 390px/التابلت 768px/الكمبيوتر 1280px بلا تجاوز أفقي.
9. أزرار التبويب قابلة للوصول بلوحة المفاتيح ولها ARIA صحيح.
10. تعمل روابط الرجوع، والاستعادة، والتنقل على نحو متوافق مع المسارات السابقة.
