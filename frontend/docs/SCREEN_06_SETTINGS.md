# الشاشة السادسة — إعدادات المستخدم وتفضيلات الواجهة

**النظام:** Bayan — نظام بيان | **المسار:** `/settings` | **نوع الشاشة:** واجهة فعلية في Next.js، تخزين تجريبي في المتصفح.

## الهدف

توحيد تفضيلات تجربة الاستخدام ضمن الهوية المرئية المعتمدة لنظام بيان (كحلي #0A2342، تركوازي #00A6B2، أبيض #FFFFFF، اتجاه RTL). تتكامل الشاشة مع `ChatLayout` ومكونات Design System السابقة. وهي نموذج Frontend غير متصل بهوية المستخدم أو قاعدة البيانات.

## أقسام الشاشة

| القسم | الحقول / السلوك | حدود التنفيذ |
|---|---|---|
| المظهر والعرض | كثافة الواجهة (مريحة/مدمجة)، حجم النص (100%/110%/120%)، تقليل الحركة، معاينة فورية | تنطبق التغييرات على نموذج المعاينة فقط، ولا تعدّل التطبيق كله |
| الإشعارات | إشعارات التطبيق والتقارير والبريد | تفضيلات محلية لا ترسل بريدًا ولا تُغيّر إشعارات مركز التنبيهات الحية |
| المحادثة | تفضيل Enter للإرسال، عرض الاستشهادات، محاكاة إجابة | لم يُربط هذا التفضيل بعد بمنطق محرر المحادثة الفعلي |
| متقدم | الدور التجريبي، إظهار SQL للمصرح لهم، صيغة التقارير للمصرح لهم | لا يمنح الدور صلاحية حقيقة أو يكشف نتائج SQL حية |

اللغة العربية وRTL ثابتان؛ الوضع الداكن غير متوفر حاليًا. التنبيهات الأمنية الإلزامية تُدار بسياسات المؤسسة ولا يمكن إيقافها من شاشة المستخدم.

## الآلية التفاعلية

1. تُحمّل البيانات الافتراضية، ثم تُقرأ قيم المعاينة المخزنة داخل هذا المتصفح من مفتاح `bayan.demo.settings.v1` إن وُجد.
2. يجري التحقق من جميع القيم المخزنة، وتُرفض المفاتيح والأنواع غير المعروفة مع العودة للقيم الافتراضية الآمنة.
3. يعدّل المستخدم التفضيلات؛ تظهر عبارة «تغييرات غير محفوظة» حتى يضغط حفظًا.
4. زر **حفظ التفضيلات** يخزّن قيم المعاينة فقط في `localStorage`، دون API أو ربط بحساب.
5. زر **إلغاء التغييرات** يعيد آخر نسخة محفوظة، و**استعادة الإعدادات الافتراضية** تستلزم نافذة تأكيد وتمسح مفتاح المعاينة.
6. يمكن اختيار دور تجريبي لإظهار/تعطيل واجهات SQL والتصدير. وصول SQL وإخراج التقارير يجب تحققه لدى الخادم وإلا لا توجد حماية بيانات.

## تكامل Backend المقترح (غير منفذ)

يلزم التنسيق مع فريق الـBackend بشأن العقود النهائية قبل تنفيذها؛ الأسماء التالية مقترحات وليست مسارات موثقة أو موجودة بالفعل:

| العملية | عقد API مقترح | ملاحظات |
|---|---|---|
| قراءة تفضيلات المستخدم | `GET /api/v1/me/preferences` | يعتمد على جلسة مستخدم مثبتة |
| حفظ التفضيلات | `PATCH /api/v1/me/preferences` | مخطط محدد، التحقق من البيانات، عزل المستأجر |
| تفاصيل الصلاحيات | `GET /api/v1/me/capabilities` | لا يقبل الدور كحقل من واجهة المستخدم |

على FastAPI فرض JWT/Session وتطبيق RBAC وتصنيف البيانات ورفض الوصول غير المصرح؛ اختفاء خيار SQL من المتصفح لا يكفي. لا تخزن كلمات المرور أو رموز الجلسات في localStorage.

## معايير القبول

- صفحة `/settings` تُحمّل في RTL وبهوية بيان.
- أربعة تبويبات منطقية مع دعم Tab ومفاتيح الاتجاه للتنقل.
- مفاتيح التبديل قابلة للاستخدام بلوحة المفاتيح وتعرض حالتها الصحيحة.
- المعاينة الفورية تعمل، والحفظ المحلي يظل بعد تحديث الصفحة.
- زر استعادة الافتراضيات يعرض حوار تأكيد قبل التنفيذ.
- عرض SQL معطل للموظف والمدير ومسؤول المنصة في مصفوفة المعاينة، ومتاح لمسؤول تقنية المعلومات فقط.
- صيغة التقرير معطلة ما لم تتوفر قدرة `reports.export` (مثال: مدير المؤسسة).
- لا يُرسل أي طلب Backend، ولا تُعرض بيانات حقيقية.
- الفحص على أحجام 390 و768 و1280 بكسل دون تمرير أفقي غير مقصود.
- لا يتغير تصميم واجهتي المحادثة ولوحة الإدارة، ولا الصفحات الخمس السابقة.
