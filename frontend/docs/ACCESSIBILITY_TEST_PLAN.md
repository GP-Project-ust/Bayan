# خطة اختبار إمكانية الوصول والتجاوب — بيان

**الهدف الهندسي المقترح:** WCAG 2.2 مستوى AA، ولا يُقصد بهذا النص وجود شهادة امتثال. يجب اختبار التفاعل الفعلي بأدوات وتقويم بشري.

## مصفوفة الأجهزة

| العرض | الاستخدام | ما يجب فحصه |
|---|---|---|
| 390px | هاتف | ظهور القائمة كدرج، منع التمرير الأفقي للصفحة، نقل التركيز، الحقول بطول مناسب |
| 768px | تابلت | ترتيب البطاقات، القائمة، الأدراج، الجداول الداخلية |
| 1280px | كمبيوتر | القائمة الثابتة، عناوين واضحة، محاذاة وقراءة الأرقام |
| 1448×1086px | مقارنة بصرية | مطابقة المرجعين المعتمدين للمحادثة والإدارة |

## بروتوكول يدوي

1. **لغة واتجاه:** وجود `lang="ar"` و`dir="rtl"` وعدم قلب SQL أو البريد أو القيم الرقمية.
2. **Tab / Shift+Tab:** وصول منطقي لجميع العناصر الظاهرة، وعدم الوصول إلى العناصر المخفية.
3. **Escape:** إغلاق Modal/Drawer، وإعادة التركيز إلى الزر فاتح النافذة.
4. **التنقل بدون ماوس:** تنفيذ العمليات اللازمة من لوحة المفاتيح فقط.
5. **الحقول:** تسميات مباشرة، ورسائل خطأ مفهومة، وتعليمات وتصحيح غير معتمد على اللون وحده.
6. **الجداول:** `<caption>` و`th scope="col"` ومنطقة تمرير قابلة للتركيز.
7. **التباين:** قياس النسب حسب مكوّن النص وحجمه، لا الاكتفاء بالمشاهدة.
8. **التكبير:** عند 200% و400%، افحص إعادة التدفق وبقاء الوظائف دون قص؛ إن تعذر فحص 400% يسجل Blocked أو Not run.
9. **تقليل الحركة:** اختبر `prefers-reduced-motion`.
10. **قارئ الشاشة:** جرّب NVDA مع Firefox أو VoiceOver مع Safari إن توافر.
11. **الحالات الديناميكية:** تتبّع رسائل `aria-live` للتحميل والأخطاء والوصول.
12. **المؤسسات والصلاحيات:** لا تظهر معلومات مقيّدة في DOM قبل تحقق API حتى لو كانت مخفية بصريًا.

## الفحص الآلي المشمول وما لا يشمله

- الفحص البنيوي يتأكد من وجود سمات RTL ومكونات الوصول والقائمة والجداول.
- Playwright يختبر تحميل المسارات وقائمة عرض 390/768/1280 وإغلاق النوافذ وحفظ سجل الجودة.
- لا يثبت أيٌّ من ذلك تباين WCAG أو نجاح قارئ الشاشة أو جودة النصوص أو حماية الوصول من جهة الخادم.

## تسجيل العيوب

لكل عيب: المسار، الجهاز/العرض، المتصفح، الخطوات، المتوقع، الفعلي، درجة الشدة، لقطة فيديو/صورة، وإصدار commit. ابدأ بحالات P0 والتداخل مع الأعمال الحساسة.
