# نظام بيان — توثيق الشاشة 13: مركز التقارير

**المسار:** `/reports`  
**التقنية:** Next.js App Router + TypeScript + React + CSS مستقل (RTL).  
**الحالة:** نموذج تفاعلي أمامي قابل للتطوير، غير موصول بقاعدة البيانات أو FastAPI.

## 1. الهدف

عرض تقارير المؤسسة وإحصائيات الجاهزية، وتسهيل البحث والتصفية وفرز النتائج، وفتح درج تفاصيل التقرير، وإتاحة تنزيل CSV **تجريبي** فقط للدور المصرح له في نموذج واجهة المستخدم. ترتبط الشاشة بمتطلبات التقارير والتحليل والتصدير (UC-03 وFR-23/24) في خطة النظام، وليس تنفيذًا لتلك المتطلبات على الخادم.

## 2. أقسام الشاشة

| القسم | العناصر |
|---|---|
| ترويسة | عنوان مركز التقارير، وصف موجز، هوية كحلي وتركوازي |
| تنبيه البيانات | إشعار ثابت بأن جميع الأسماء والمقاييس والمصادر خيالية |
| محاكاة الدور | محدد دور عرض: موظف المؤسسة، مدير المؤسسة، مسؤول تقنية المعلومات، مسؤول المنصة |
| مؤشرات | إجمالي التقارير، جاهزة، قيد الإنشاء، مسودات أو بحاجة لمراجعة |
| البحث | نص عربي وتطبيع همزات وتشكيل، نوع، حالة، شهر، ترتيب |
| الجدول | عنوان التقرير ووصفه، النوع، الجهة والفترة، التاريخ، الحالة، الإجراءات |
| درج التفاصيل | المصدر، المدة، التصنيف، المؤشرات، مخطط أعمدة CSS، تنبيه تجريبي |
| الصيغ | تنزيل CSV محلي؛ PDF وExcel محجوزان للشاشة اللاحقة |

## 3. بيانات التدريب

- 12 تقريرًا خياليًا معرفًا داخل `lib/reports/reports.ts` مع معرفات `rep-101` إلى `rep-112`.
- الحالات: `ready`، `processing`، `failed`، `draft`.
- الأنواع: `academic`، `operational`، `analytical`، `regulatory`.
- التقارير ليست مصدرًا مؤسسيًا حقيقيًا، ولا تمثل استعلامات SQL منفذة.
- التقارير غير الجاهزة لا تحتوي على نتائج مصطنعة معروضة كأنها نهائية.

## 4. الأدوار وضوابط المعاينة

| الدور | عرض القائمة | إنشاء تقرير | تصدير CSV |
|---|---|---|---|
| موظف المؤسسة | نعم | لا | لا |
| مدير المؤسسة | نعم | رابط إلى قالب `/reports/new` | نعم للتقارير الجاهزة |
| مسؤول تقنية المعلومات | نعم | لا | لا |
| مسؤول المنصة | لا، منع عرض محلي | لا | لا |

هذه مصفوفة *تصميم واجهة فقط*؛ يجب تنفيذ التحقق من هوية المستخدم والمستأجر ونطاق البيانات والصلاحيات داخل FastAPI وقاعدة البيانات، خصوصًا عند استخراج CSV.

## 5. تدفق الاستخدام

1. فتح `/reports` ثم تحقق عرض تجريبي من `reports.view`.
2. عرض الإحصائيات العامة والقائمة (أمثلة محلية).
3. يغيّر المستخدم البحث والتصنيف والحالة والشهر والترتيب.
4. عند اختيار تقرير يفتح درج التفاصيل؛ الحالة `ready` فقط تعرض المؤشرات والقيم.
5. يظهر زر التصدير فقط مع `reports.export` وتقرير `ready` ذي صفوف متاحة.
6. ينشئ المتصفح CSV بترميز UTF-8 BOM ويتضمن تصريحًا واضحًا بأن البيانات تجريبية؛ القيم التي تبدأ بصيغة جدول حسابي تُحمى من تنفيذ الصيغ (CSV injection).
7. زر إنشاء تقرير جديد يفتح **قالبًا موجودًا من كتالوج الشاشات** على `/reports/new`؛ سنبني نموذج الإنشاء الفعلي في الشاشة 14.

## 6. حدود التنفيذ

- **لا يوجد API** لإنشاء التقارير أو تحديث الحالة أو تنزيل ملفات رسمية.
- **لا توجد صيغ PDF أو Excel فعلية** في هذه الشاشة؛ النقر على زرها يعرض تنبيهًا عن المرحلة اللاحقة.
- لا يوجد تخزين في `localStorage` أو `sessionStorage` لتقارير تجريبية.
- تتغير المرشحات في الذاكرة المؤقتة للصفحة فقط، دون حفظ.
- دور المستخدم متغير تجريبي، وليس مصادقة أو تصريحًا أمنيًا فعليًا.

## 7. عقود API المقترحة للمستقبل (غير منفذة)

| Method | Route مقترح | الغرض | الحماية |
|---|---|---|---|
| GET | `/api/v1/reports` | قائمة تقارير المستأجر | `reports.view` + فحص المؤسسة |
| GET | `/api/v1/reports/{id}` | التفاصيل وبيانات التقرير المصرح بها | RBAC + Row/Tenant Level Scope |
| POST | `/api/v1/reports` | إنشاء مهمة تقرير | `reports.create` |
| GET | `/api/v1/reports/{id}/status` | حالة المهمة | مالك أو مخوّل |
| GET | `/api/v1/reports/{id}/export?format=csv` | تصدير آمن | `reports.export` + فحص تصنيف البيانات |

المسارات أعلاه **مقترحات تصميمية لا ادعاء بأنها موجودة في Backend**.

```bash
npm run check:reports
npm run dev
```

```bash
npx playwright test tests/e2e/reports.spec.ts
```

معايير القبول: تظهر 12 بطاقة/صفًا؛ البحث العربي والتصنيف وحالة الفراغ يعملان؛ درج التفاصيل يعرض المصدر؛ يمنع التصدير عند غياب الصلاحية أو عدم جاهزية التقرير؛ CSV يحمل تحذيرًا تجريبيًا ويتجنب CSV formula injection؛ الواجهة لا تفتح اتصالات Backend؛ لا يوجد تمرير أفقي للصفحة عند 390px (مع إمكانية تمرير الجدول داخل حاويته).
