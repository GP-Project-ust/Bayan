# الشاشة 03 — إعادة تعيين كلمة المرور (Reset Password)

**المشروع:** بيان (Bayan) — واجهات المستخدم باستخدام Next.js / React / TypeScript  
**المسار:** `/reset-password`  
**المسار التجريبي للنموذج:** `/reset-password?preview=valid` (في بيئة التطوير فقط)  
**المرجع البصري:** واجهة تسجيل الدخول الأصلية وشاشة الاستعادة؛ هوية RTL الكحلي والتركوازي والأبيض.  
**التصنيف:** شاشة فرعية لتدفق «استعادة الحساب»، وليست شاشة رئيسية إضافية ضمن قائمة الشاشات الـ42.

## الهدف

إتاحة واجهة رسمية لإعداد كلمة مرور جديدة بعد التحقق الفعلي من رابط إعادة التعيين على الخادم مستقبلًا. النسخة الحالية **نموذج واجهة تفاعلي فقط**، ولا تعيد تعيين كلمات المرور فعلًا.

## المكونات

- `app/reset-password/page.tsx`: مسار App Router مع `metadata` لتعطيل الفهرسة وتقليل إحالة المعلومات.
- `components/auth/ResetPasswordScreen.tsx`: نموذج كلمة المرور الجديدة والتأكيد، عداد القوة والمتطلبات، مؤشرات التحقق، حالات الروابط ونتيجة التجربة.
- `lib/auth/reset-password.ts`: دوال تحقق نقية (مناسبة لاختبارات الوحدة) ودوال تقرير حالة المعاينة.
- `components/auth/reset-password.css`: تصميم منفصل متوافق مع `login.css` و`recovery.css` ولا يعدل الشاشات السابقة.
- `tests/e2e/reset-password.spec.ts`: سيناريوهات Playwright لاختبار المسار والحالات والنماذج والتجاوب.

## حالات تجربة الواجهة

| الرابط | المعنى | المتوقع |
|---|---|---|
| `/reset-password` | لا يوجد رابط | حالة «يلزم رابط لإعادة التعيين» |
| `/reset-password?preview=valid` | رابط تجريبي صالح | نموذج كلمة المرور |
| `/reset-password?preview=expired` | رابط تجريبي منتهي | حالة انتهاء الصلاحية وطلب استعادة جديدة |
| `/reset-password?preview=invalid` | رابط تجريبي غير صالح | حالة رفض الرابط وطلب استعادة جديدة |
| `/reset-password?token=anything` | رمز حقيقي/مجهول | حالة «التحقق الآمن غير متاح حاليًا»؛ لا يُقبل الرمز ولا يُعرض |

**ملحوظة:** يتم تعطيل وضع المعاينة في بيئة الإنتاج افتراضيًا، ما لم يفعّله الفريق صراحةً بمتغير `NEXT_PUBLIC_BAYAN_RESET_PREVIEW=1`، وهو **غير موصى به في نشر حقيقي**.

## قواعد الإدخال

- كلمة المرور مطلوبة؛ الطول بين 12 و128 حرفًا Unicode.
- تحتوي على حرف واحد ورقم واحد ورمز خاص على الأقل.
- التأكيد مطلوب، ومطابق لكلمة المرور الجديدة.
- الحقلان يستخدمان `autocomplete="new-password"` مع إخفاء القيمة افتراضيًا وزري إظهار مستقلين.
- مؤشر استيفاء المتطلبات مرئي وناطق عبر `role="meter"`، ومتطلبات الأمان تظهر بحالات تحقق واضحة. **هذا المؤشر تقديري وليس قياسًا رياضيًا لقوة كلمة المرور ولا فحصًا لكلمات مرور مسرّبة.**
- بعد نجاح تجربة التحقق، تُفرّغ قيم الحقلين من حالة React، دون تسجيلها أو حفظها.

هذه قواعد **تجربة واجهة**؛ يجب تحديد سياسة كلمة المرور الإنتاجية وفق متطلبات المؤسسة وأفضل الممارسات، وتطبيقها والتحقق منها على الخادم.

## الأمان والتكامل المطلوب

النسخة الحالية لا ترسل `fetch` ولا تولّد رموزًا ولا تستخدم تخزين المتصفح لكلمات المرور. في التكامل المستقبلي يجب تنفيذ:

1. خدمة إرسال رابط استعادة آمن عبر البريد المؤسسي مع رد موحد لا يكشف وجود الحساب.
2. رمز عشوائي قوي قصير الصلاحية، أحادي الاستخدام، يخزن خادمياً كقيمة مجزأة، ويرتبط بحساب ووقت انتهاء.
3. نقطة Backend للتحقق من صلاحية الرمز قبل تقديم نموذج فعلي.
4. نقطة Backend لقبول كلمة المرور الجديدة وإعادة التحقق من الرمز وصلاحية الإدخال ومعدل الطلبات، ثم استهلاك الرمز بصورة ذرّية وإبطال الجلسات حسب السياسة.
5. سجل تدقيق **لا يتضمن** كلمات المرور أو الرموز؛ ومنع تخزين/عرض الرموز في أدوات التحليل أو السجلات أو URL referrer.
6. حماية CSRF أو غيرها بحسب طريقة الجلسات والتوثيق، وTLS، ومراقبة الإساءات.

لا يمكن اعتبار حراسة `preview` على الواجهة تحققًا أمنياً؛ تظل جميع سياسات الهوية والرموز والجلسات إلزامية على Backend.

## معايير قبول الشاشة

- [ ] تماثل ألوان وخط وتخطيط واجهة تسجيل الدخول على سطح المكتب.
- [ ] رابط مفقود يعرض حالة مناسبة.
- [ ] رابط تجريبي منتهي/خاطئ يعرض رسائل وأزرار واضحة.
- [ ] رمز URL فعلي لا يقبل التحقق منه في النموذج التجريبي.
- [ ] الحقول تعرض أخطاء الحقل الأول والتركيز على الحقل المناسب.
- [ ] يدعم إظهار كلمات المرور وإخفاءها بشكل مستقل.
- [ ] بعد اكتمال النموذج تظهر نتيجة **تجريبية فقط**، دون API.
- [ ] يعمل الاتجاه RTL، ولا يظهر تمرير أفقي على 390 / 768 / 1280 بكسل.
- [ ] يعمل التنقل باللوحة والتركيز المرئي.
- [ ] تُجرى اختبارات Next.js والتكامل الحقيقي في بيئة تطوير الفريق قبل النشر.
