# تسليم Frontend إلى فريق Backend — Bayan

## حدود هذا الإصار

الموجود حاليًا: تصميمان مرجعيان + مكونات عامة ومجالية + 42 تعريف مسار + نماذج واجهة تجريبية + مصفوفة أدوار للمعاينة + أدوات QA. غير الموجود: اتصال موثق بـAPI الإنتاج، مصادقة وجلسة حقيقية، فحص صلاحية خادم، استعلام قاعدة بيانات حي، توليد تقرير PDF/XLSX من الخادم، تدقيق حي.

## نقاط ربط مطلوبة — عقود مقترحة لا يجوز ادعاء تنفيذها

| وظيفة UX | عقد تكامل مقترح | ملاحظة |
|---|---|---|
| إرسال سؤال | `POST /api/chat` مع stream SSE عند توفره | يُثبت المسار النهائي من كود FastAPI أولًا |
| فحص الخدمة | `GET /health` أو المسار الفعلي | لا يعتمد مسار تخميني دون مراجعة Backend |
| تسجيل الدخول | جلسة/Token من Backend | cookie محمية HttpOnly/SameSite عند ملاءمتها |
| الصلاحيات | نتيجة تحقق من Backend لكل endpoint | لا تثق بـ `lib/access/policy.ts` كحاجز أمني |
| SQL المصرح به | payload مُرشّح للخادم | لا تُرسل SQL إلى مستخدم غير مخوّل حتى لو كان العنصر مخفيًا |
| مصادر RAG | عنوان المستند + معرف مصدر + رقم الصفحة | تحقق من أذونات المؤسسة والوثيقة |
| التقارير | API تنزيل يحدد MIME واسم الملف | نموذج الواجهة الحالي PDF للطباعة وExcel XML |
| Smart Views | قوائم/إضافة/تصنيف من الخادم | Public, Masked, Restricted, Blacklist تحتاج إنفاذًا حقيقيًا |
| سجل التدقيق | سجل تنفيذي متحقق الصلاحيات | تجنب عرض بيانات حساسة أو أسرار |
| تتبع الوكلاء | أحداث تشغيلية مختصرة | لا تُظهر استدلال النموذج الداخلي |

## تحضير التذاكر التقنية

1. حدّد فقط مسارات API الموجودة بالفعل في كود الخادم، مع schema request/response ومرجع مسؤول Backend.
2. اكتب عميل API في `lib/api/` يدعم AbortController، الحالات 400/401/403/429/500 والانقطاع، وإلغاء الطلب.
3. اربط الـstates وحالات التحميل بـSSE إن نُفّذ فعليًا؛ تجنب معالجة نتائج مزيفة كحقيقة.
4. اكتب اختبارات تكامل API للحسابات الأربعة مع مؤسسة ثانية للتحقق من العزل.
5. استبدل بيانات demo واعتمد ترجمات الأخطاء باللغة العربية ومراجعة الأمن قبل التشغيل الحقيقي.

## فحوص أمنية ضرورية

- تحقق AuthN/AuthZ على كل endpoint؛ tenant scope على كل استعلام وصف وعرض ذكي ومستند.
- استعلام SQL read-only/allowlist، مهلات، حد حجم النتيجة، منع الأدوات ذات الصلاحيات غير الضرورية.
- تصنيف المصادر حسب مستوى الوصول، ومنع التحايل عبر prompt injection أو URL غير مصرح بها.
- سجلات تدقيق عملية مع إخفاء بيانات شخصية أو مفاتيح اعتماد.
- عدم إظهار أسرار API أو أخطاء tracebacks التفصيلية للمستخدم النهائي.

**التسليم:** يمكن بدء ربط المحادثة والتحقق من الخدمة أولًا، لكن يمنع وصف النظام بأنه آمن أو جاهز للإنتاج إلى حين اجتياز اختبارات التكامل والأمن.
