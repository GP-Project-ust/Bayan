# الشاشة 14 — معالج إنشاء تقرير ذكي | Bayan Smart Report Builder

**مسار Next.js:** `/reports/new`  
**التقنية:** Next.js App Router، React، TypeScript، CSS معزول وRTL، ومكتبة مكونات بيان.  
**الحالة:** واجهة أمامية تجريبية؛ لا توجد عملية إنشاء تقرير على الخادم أو استخراج بيانات من قاعدة المؤسسة.

## 1. الهدف

تغطية مرحلة **إعداد طلب التقرير** من حالة الاستخدام UC-03 (التقارير والتحليلات) بالاعتماد على Design System المعتمد. تستقبل الواجهة عنوان التقرير والغاية منه، وتُظهر خيارات مصادر ومؤشرات تدريبية متوافقة، وتسمح بتحديد فترة تجريبية وتجميع النتائج، ثم مراجعة طلب الإعداد دون إنشاء نتائج أو ملفات فعلية.

## 2. الخطوات والمكونات

| الخطوة | عناصر الواجهة | متطلبات التحقق |
|---|---|---|
| 1: بيانات التقرير | عنوان التقرير، الهدف، النوع، مستوى الظهور المقترح | عنوان 8–100 حرف، هدف 20–500 حرف |
| 2: المصادر والمؤشرات | 5 مصادر تدريبية، 10 مؤشرات مرتبة حسب المصدر | مصدر واحد على الأقل؛ 1–6 مؤشرات، متوافقة مع مصادرها |
| 3: الفترة والعرض | تاريخ البداية، النهاية، طريقة التجميع، إظهار المصادر والنقاط الرئيسية | تواريخ ميلادية صحيحة، البداية ≤ النهاية، نطاق ≤ 1095 يومًا |
| 4: المراجعة | قائمة كاملة بالخيارات، تنزيل JSON، حوار تأكيد | إعادة التحقق من الخطوات 1–3 قبل التقديم |

### السلوك التفاعلي

- أزرار **التالي** و**السابق**، ومؤشر تقدم (25% / 50% / 75% / 100%).
- نموذج جاهز باسم «توزيع الطلاب حسب الكليات — تقرير تجريبي» لعرض مراحل الإنشاء، ويمكن تغييره يدويًا.
- عند إلغاء مصدر، تُحذف مؤشرات ذلك المصدر تلقائيًا ولا يمكن تفعيلها حتى إعادة اختياره.
- معاينة جانبية لتكوين التقرير دون إيهام بوجود نتائج رقمية أو مخططات حقيقية.
- خيار **تنزيل إعدادات JSON** من الواجهة بعد تحقق الحقول: ملف تكوين فقط يحوي تنبيهًا بتجريبية المعلومات.
- تأكيد نهائي في Dialog يعرض صفحة «اكتملت محاكاة إعداد التقرير» ولا يضيف سجلًا إلى مركز التقارير؛ توجد خيارات للبدء مجددًا أو الرجوع إليه.
- مسح النموذج يتطلب تأكيدًا منفصلًا.

## 3. الأدوار

طبقة عرض تجريبية وفق `lib/access/policy.ts`: **مدير المؤسسة** يمتلك `reports.create`؛ **موظف المؤسسة، مسؤول تقنية المعلومات، ومسؤول المنصة** لا يستطيعون إظهار نموذج الإنشاء في المحاكاة. صلاحيات الواجهة ليست مصدرًا موثوقًا للتحكم في الوصول؛ على FastAPI التحقق من هوية المستخدم والجهة والصلاحيات عند كل طلب، ومن حدود مصادر البيانات ومستوى التصنيف.

## 4. البيانات التجريبية

الملف `lib/reports/builder.ts` يتضمن: مصدر الطلاب، وسجلات التسجيل، والأداء الأكاديمي، والحضور والغياب، والمستندات التنظيمية؛ لكل مصدر مؤشرات محددة مسبقًا. جميعها مصطلحات وأمثلة لتجربة التخطيط ولا تعكس مصادر حقيقية أو عروضًا ذكية منشورة.

### التصدير

- ملف JSON اختياري يحفظ **اختيارات النموذج فقط** محليًا باستخدام Blob API؛ لا يتضمن بيانات مؤشرات ولا ملفات أو بيانات مستخدمين.
- لا يصدر CSV أو PDF أو Excel من هذه الشاشة؛ تلك تخص المرحلة التالية «معاينة التقرير وتصديره».
- التغييرات داخل الذاكرة في الصفحة فقط؛ لا يوجد حفظ تلقائي أو اتصال API.
- لا يتم إنشاء مسودة دائمة داخل `/reports`، حتى لو اكتملت محاكاة الخطوة الرابعة.

## 5. عقود Backend المقترحة وغير المنفذة

| Method | مسار افتراضي | الغرض | شرط الحماية |
|---|---|---|---|
| GET | `/api/v1/report-sources` | عرض المصادر والمؤشرات المتاحة للمستخدم | حدود المؤسسة والتصنيف، `reports.create` |
| POST | `/api/v1/reports` | إنشاء مهمة التقرير والتحقق من الطلب | `reports.create`، تحقق المصادر ونطاق المؤسسة |
| GET | `/api/v1/reports/{id}/status` | تتبع حالة إنشاء التقرير | صلاحية المستخدم وحدود المستأجر |
| GET | `/api/v1/reports/{id}` | عرض التقرير الناتج بعد التجهيز | فحص المصدر والهوية وحدود العرض |

هذه المقترحات لا تعني أن المسارات موجودة أو نُفذت؛ ولا يجب الوثوق بتكوين JSON القادم من المتصفح، بل يُعاد التحقق منه بالكامل على الخادم.

## 6. معايير القبول

1. وجود الخطوات الأربع وإظهار الخطوة الحالية والقيم المختارة.
2. منع الانتقال عند عنوان أو هدف غير صالح، أو عدم اختيار مصادر ومؤشرات.
3. حذف المؤشرات التابعة عند إزالة مصدرها.
4. رفض التواريخ غير المنطقية، ومنع فترات تزيد على ثلاث سنوات.
5. إظهار صفحة مراجعة للتكوين دون مؤشرات أرقام وهمية على أنها حقيقية.
6. عمل تنزيل ملف JSON عند صحة النموذج.
7. عدم إظهار نموذج الإنشاء عند غياب `reports.create` في محاكاة الدور.
8. إظهار تأكيد صريح بأن «الإعداد مكتمل تجريبيًا فقط» دون سجل جديد في التقارير.
9. نجاح التنقل بعرض 390، 768، 1280 بكسل، واستخدام لوحة المفاتيح وRTL.
10. الحفاظ على واجهات المحادثة والإدارة ومركز التقارير السابقة.

## 7. الاختبارات والتشغيل

```bash
npm install
npm run check:report-builder
npm run lint
npm run build
npm run dev
```

الصفحة `http://localhost:3000/reports/new`. اختبارات المتصفح تتطلب Playwright:

```bash
npx playwright test tests/e2e/report-builder.spec.ts
```

**حدود التحقق:** اختبارات العقود البرمجية وفحص الصياغة ليست بديلًا عن تشغيل Next.js فعلًا ولا إثباتًا للتطابق البصري على أجهزة مختلفة.
