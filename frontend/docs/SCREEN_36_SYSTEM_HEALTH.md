# الشاشة 36 — مراقبة صحة خدمات نظام بيان

**المسار:** `/platform/health`  
**الواجهة:** `SystemHealthScreen.tsx`  
**الدور:** مسؤول المنصة (محاكاة `platform.manage`)  
**الحالة:** واجهة أمامية تجريبية، غير متصلة بـBackend.

## التصميم والوظائف

- هوية بيان: كحلي `#0A2342`، وتركوازي `#00A6B2`، ومساحات بيضاء وRTL.
- بطاقات إحصائية لحالات الخدمات الثماني الاصطناعية.
- صفحة الخدمات: البحث، التصفية حسب المجموعة والحالة، نتائج جدولية، تفاصيل، وتاريخ عينات وهمية.
- صفحة التنبيهات: البحث والتصفية حسب مستوى الخطورة والحالة والنطاق الزمني الوهمي، وتفاصيل التنبيه.
- «فحص محلي تجريبي» لا يجري أي طلب HTTP ولا يقيس زمن استجابة.
- تصدير CSV تجريبي مع حماية من صيغ الجداول وحجب البيانات الحساسة.
- درجة الوصول محاكاة في الواجهة فقط؛ لا يعتمد عليها Backend.
- دعم الأجهزة الصغيرة واستخدام لوحة المفاتيح وواجهات Dialog/Drawer الموجودة في Design System.

## نطاق الخدمات

FastAPI وPostgreSQL وQdrant وLangGraph وOllama، مع Redis وReporter Worker وDocument Indexer بصفتها **عينات تشغيل اختيارية**؛ وجودها في العرض لا يثبت وجودها بالفعل في خادم بيان.

## حالات العمل

1. يفتح مسؤول المنصة `/platform/health`.
2. تُعرض ملاحظة واضحة بأن كل القيم اصطناعية.
3. يُدخل مرشحات الخدمات أو التنبيهات.
4. يفتح درج التفاصيل أو ينفذ فحصًا محليًا تجريبيًا.
5. يمكنه تصدير CSV للعناصر الظاهرة.
6. لا يستطيع الدور غير المخوّل عرض اللوحة.

## التكامل المستقبلي المقترح (غير منفذ)

| Method | Endpoint مقترح | الاستخدام |
|---|---|---|
| GET | `/api/v1/platform/health/services` | حالات خدمة مجمّعة مأذون بعرضها |
| GET | `/api/v1/platform/health/services/{id}` | تفاصيل قياسات الصحة ووقت تسجيلها |
| POST | `/api/v1/platform/health/checks` | طلب فحص على الخادم بعد RBAC وحدود المعدل |
| GET | `/api/v1/platform/health/alerts` | تنبيهات تشغيلية ومنشأها ومعلومات الارتباط |

**هذه المسارات تصميم مقترح، وليست ادعاءً بأنها موجودة في FastAPI.** ينبغي على الخادم تنفيذ مصادقة وتفويض وعزل مؤسسي وسجل تدقيق وحماية الأسرار، وإرجاع مصدر القياس ووقته وصلاحيته. يجب تجنب إرجاع مفاتيح API وكلمات المرور وسلاسل الاتصال.

## فحوص الفريق

- `npm run check:system-health` لفحص الملفات وعقود الشاشة.
- `node --test tests/contracts/*.test.mjs` للفحوص المتراكمة.
- `npm run lint && npm run build` بعد تثبيت npm.
- `npx playwright install chromium && npm run test:e2e` للاختبار الفعلي في المتصفح.

الفحوص البرمجية لا تعني أن بناء Next.js أو التطابق البصري قد تحقق؛ يجب اختبارهما منفصلين.
