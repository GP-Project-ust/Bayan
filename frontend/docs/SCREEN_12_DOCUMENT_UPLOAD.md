# بيان — الشاشة 12: رفع المستندات وفهرستها

## حالة التنفيذ

**منجز كنموذج واجهة Frontend تفاعلي**. لم تُنفذ عملية رفع، أو تخزين، أو استخراج نصوص، أو فهرسة دلالية على الخادم. اسم الملف والحجم بيانات يقدّمها المتصفح، ولا يقرأ التطبيق بايتات الملف. يُمنع الاعتماد على درجة التقدم التجريبية بوصفها نتيجة خدمة حقيقية.

## 1. المسارات والروابط

- المسار الجديد: `/sources/upload`.
- الوصول إليه من صفحة `/sources` عن طريق **رفع مستند** بعد اختيار دور «مسؤول تقنية المعلومات» في المحاكاة.
- زر العودة إلى مكتبة المستندات `/sources`.
- بيانات الكتالوج `/lib/screen-catalog.json` محدثة بحيث يرتبط رفع المستندات بدور IT داخل المؤسسة.

## 2. التصميم

يعيد استخدام `ChatLayout` والهوية البصرية السابقة دون إعادة كتابة `ChatView` أو `AdminDashboard` أو `app/globals.css`. الألوان الأساسية: كحلي `#0A2342` وتركوازي `#00A6B2`، خلفيات فاتحة، خط عربي واتجاه RTL. عناصر الشاشة ضمن نطاق CSS مستقل `bdu-*` حتى لا تتسرب التنسيقات إلى واجهات أخرى.

### أقسام الشاشة

1. مسار تنقل Breadcrumb، ترويسة رئيسية، وتحذير صريح بأن الصفحة تجريبية.
2. محدد دور تجريبي؛ الواجهة مخصصة لمسؤول تقنية المعلومات ولا تسمح لبقية الأدوار بتجربة العمليات.
3. مؤشر خطوات ثلاث: اختيار الملفات، بيانات المستندات والصلاحيات، محاكاة المعالجة.
4. أربع بطاقات مؤشرات للملفات المحفوظة مؤقتًا في حالة React.
5. منطقة سحب وإفلات واختيار ملفات (متعددة).
6. قائمة ملفات: الاسم والحجم والتصنيف ومستوى الوصول والحالة والتقدم وأزرار التفاصيل والإزالة والإلغاء/إعادة المحاولة.
7. نموذج تصنيف المستند والجهة المالكة ومستوى الوصول والوصف.
8. قائمة مراحل المعالجة مع زر بدء المحاكاة.
9. درج جانبي لبيانات الملف، ونافذة تأكيد مسح القائمة، ورسائل Toast للحالات.

## 3. سياسات الفحص المحلي

| القيد | التطبيق في النموذج |
|---|---|
| الامتدادات المقبولة | `.pdf`, `.docx`, `.txt` |
| أقصى حجم للملف | `20 MiB` |
| أقصى عدد في القائمة | `6` ملفات |
| الملفات الفارغة | مرفوضة |
| المسارات ضمن الاسم أو رموز التحكم | مرفوضة |
| الملف المكرر | لا يعاد إدراجه |
| الجهة المالكة | بين 3 و90 حرفًا |
| الوصف | لا يزيد عن 350 حرفًا |
| مستوى الوصول | داخلي / مقيّد / حساس |
| التصنيف | اللوائح / الأدلة / السياسات / النماذج |

**تنبيه أمني:** هذه القيود لتحسين تجربة المستخدم فقط. يمكن تغيير امتداد الملف والتلاعب ببيانات المتصفح. ينبغي التحقق مرة أخرى على FastAPI: هوية المستخدم والمؤسسة، وحدود النوع والحجم الحقيقية، وتوقيع/صيغة الملف، والفحص ضد الملفات الخبيثة، وسياسات التخزين ومدة الاحتفاظ، ومستوى السرية، وإمكانية الفهرسة. مستوى الوصول داخل الشاشة لا يحمي أي بيانات فعليًا.

## 4. مخطط تدفق الواجهة

1. فتح المسار والتحقق من صلاحية العرض التجريبية.
2. اختيار ملفات فعلية (**اسم وحجم فقط**) أو توليد اسمَي ملف للتجربة.
3. فحص أولي لكل ملف. تظهر الملفات المرفوضة مع السبب بدل حذفها دون تفسير.
4. تحديد بيانات الدفعة، ثم التحقق من الجهة المالكة والوصف والتصنيف والمستوى.
5. بدء محاكاة محلية بمؤقتات React، مع مراحل: فحص، استقبال، استخراج نص، تقسيم مقاطع، إنشاء متجهات، واكتمال المحاكاة.
6. يمكن الإلغاء أثناء العمل ثم إعادة المحاولة، أو إزالة الملف أو مسح القائمة بعد التأكيد.
7. تنتهي العملية برسالة **«لم تُضف إلى المكتبة أو Qdrant»**.

الملفات: `docs/flows/20-document-upload-flow.mmd`, `.dot`, `.png`, `.svg`.

مواقع التكامل المعدلة فقط:

- `lib/screen-catalog.json` — مواءمة الدور وملاحظة أن العمل تجريبي.
- `package.json` — إضافة `check:document-upload`.
- `README.md` — إضافة دليل الاستخدام الجديد.

## 6. حالات القبول والاختبار

- يستطيع مسؤول تقنية المعلومات اختيار ملفات مدعومة والتحقق من ظهورها في قائمة الانتظار.
- تظهر رسالة رفض واضحة لملف `.exe` والملف الفارغ والملف الأكبر من 20 ميجابايت.
- لا يضاف ملف مكرر أو ما يتجاوز ستة ملفات في قائمة واحدة.
- تُرفض بيانات الجهة المالكة إذا كانت قصيرة جدًا أو طويلة جدًا.
- لا يبدأ التقدم إذا لم تتوفر ملفات جاهزة أو بيانات وصفية صالحة.
- يمر الملف عبر المراحل المعرّفة ويعرض التقدم بشكل واضح على أنه محاكاة.
- يمكن إلغاء المحاكاة وإعادة المحاولة ومسح القائمة بعد التأكيد.
- الأدوار الأخرى لا ترى أدوات الرفع أثناء عرض شاشة المنع التجريبية.
- يمكن العودة إلى المكتبة مباشرة، ولا تظهر ملفات نموذجية جديدة فيها على أنها مفهرسة.
- على الهاتف 390px لا يوجد تمرير أفقي غير مقصود.

التحقق البنيوي:

```bash
npm run check:document-upload
```

اختبار المتصفح (بعد تثبيت الاعتماديات):

```bash
npx playwright install chromium
npx playwright test tests/e2e/document-upload.spec.ts
```

> التحقق البرمجي البنيوي لا يضمن نجاح بناء Next.js في المتصفح؛ تحتاج النسخة إلى `npm install && npm run build` وتجربة المستخدم على جهاز التطوير.

## 7. عقود Backend المقترحة — وليست مسارات منفذة

**لا نضيف هذه المسارات إلى Frontend في هذه الشاشة، ولا نفترض وجودها في الشيفرة الحالية.** عند جاهزية فريق Backend يمكن مراجعة العقود التالية ثم اعتمادها:

| العملية | نموذج عقد مقترح | متطلبات الأمان |
|---|---|---|
| تقديم المستند | `POST /api/v1/documents` | multipart، تحقق من الصلاحية والمؤسسة والفحص الأمني |
| حالة المعالجة | `GET /api/v1/documents/{id}/status` | هوية المؤسسة وصلاحية الاطلاع |
| إعادة فهرسة مستند | `POST /api/v1/documents/{id}/reindex` | دور IT أو صلاحية مفوضة + تدقيق |
| عرض المستندات | `GET /api/v1/documents` | تصفية إلزامية بحسب المؤسسة ومستوى الوصول |
| تتبع العمليات | يحدد مع فريق Backend | تسجيل النشاط والأخطاء بدون تسريب المحتوى |

اقتراح طبقة عملية: التحقق من الملفات واستخراج النص بصورة معزولة، ثم تقطيع المقاطع وتوليد embeddings وتحميلها إلى Qdrant، وتسجيل حالة المعالجة ومعلومات المصدر في PostgreSQL. لا يتضمن هذا النموذج تطبيق تلك الخدمة.
