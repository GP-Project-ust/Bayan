# الشاشة 30 — تتبع تنفيذ الوكلاء (Agent Traces)

**المسار:** `/admin/agent-traces`  
**حالة التنفيذ:** نموذج تفاعلي تدريبي؛ غير متصل بالـBackend  
**المتطلبات ذات الصلة:** UC-06 — مراقبة تنفيذ العمليات، وتتبع مراحل الوكلاء  
**التصميم:** الهوية المعتمدة لنظام بيان؛ كحلي `#0A2342` وتركوازي `#00A6B2`، Cairo/RTL، وإعادة استخدام `AdminLayout` و`DemoAccessProvider` و`Drawer`.

## الهدف

تمكين مسؤول تقنية معلومات المؤسسة من مراجعة المسارات التشغيلية **المصرح بها** التي تمر عبر الوكلاء الخمسة: `Supervisor`, `SQL`, `RAG`, `Analyst`, `Reporter`. تعرض الشاشة معلومات التشغيل الوصفية، ولا تتضمن سلسلة التفكير الداخلية للنماذج أو النصوص الخام للأسئلة أو SQL التنفيذي أو أسرار الاتصال.

## العناصر

1. بطاقات إجمالي العمليات، الناجحة، والفاشلة/المرفوضة، والجارية (عرض ثابت).
2. جدول 8 سجلات تدريبية، يحتوي على وقت البدء ومعرّف التتبع ونوع المهمة والوكلاء المشاركين والمدة والنتيجة.
3. بحث بالعربية (مع تطبيع التشكيل والهمزات)، وتصنيف بحسب الحالة ونوع المهمة والوكيل والفترة الزمنية.
4. درج تفاصيل يعرض تسلسل الخطوات التشغيلية وأسماء الوكلاء ومددهم وحالاتهم والملخص الآمن لكل خطوة، مع إمكانية توسيع تفاصيل كل مرحلة.
5. نسخ مرجع التتبع، وتصدير CSV تدريبية مع حماية قيم الصيغ الضارة عند فتح الملف في جداول البيانات.
6. رابط من عمليات متطابقة مع عينات التدقيق إلى صفحة تفاصيل حدث التدقيق `/admin/audit/details?id=...`، من دون الادعاء بأن هناك سجلات حقيقية مرتبطة.
7. منع عرض السجل للأدوار غير المخوّلة في محاكاة RBAC.

## مصادر البيانات والحدود

- `lib/agent-traces/traces.ts`: 8 عمليات **اصطناعية ثابتة**؛ ثلاث منها تشترك في المعرّف مع أحداث تدريبية موجودة في `lib/audit/events.ts` (`TRACE-DEMO-0007`, `TRACE-DEMO-0012`, `TRACE-DEMO-0013`).
- لا توجد استدعاءات `fetch` أو WebSockets أو EventSource، ولا يُسجَّل أو يُخزّن نشاط المستخدم الفعلي.
- حالة `running` مرئية ثابتة للعرض؛ **لا توجد عملية تعمل في الخلفية**.
- مسؤول المنصة لا يرث صلاحية تتبع عمليات مؤسسة تلقائيًا. يجب عزل سجلات المنصة عن سجلات المؤسسات في الخادم.
- لا تنتج هذه الشاشة سجلًا قابلًا للاعتماد في تدقيق الإنتاج؛ المصدر الموثوق سيكون مراقبة Backend المركزية بعد التطوير.

## ربط الإنتاج المقترح (غير منفّذ)

| الوظيفة | تصميم API مقترح | الأمان المطلوب |
|---|---|---|
| قائمة المسارات | `GET /api/v1/admin/agent-traces?status=&agent=&from=&to=` | جلسة موثقة وصلاحية `traces.view` مع `tenant_id` مفروض في الخادم |
| تفاصيل مسار | `GET /api/v1/admin/agent-traces/{trace_id}` | فحص المؤسسة لكل خطوة، وإخفاء القيم الحساسة |
| التصدير | `POST /api/v1/admin/agent-traces/export` | حد أقصى للصفوف، وتسجيل طلب التصدير في سجل التدقيق |

**لا تعتبر هذه المسارات موجودة أو مطبقة**؛ وهي مواصفات للربط مستقبلًا. لا يُسمح للعميل بإرسال `tenant_id` قابل لتجاوز عزل البيانات دون تحقق الخادم.

## معايير القبول

- يستطيع مسؤول تقنية المعلومات رؤية المكونات، بينما يُحجب الجدول والدرج والتصدير عن الموظف والمدير ومسؤول المنصة.
- يمكن البحث بحسب معرّف التتبع والوكيل العربي أو الإنجليزي، والتصفية بحسب النوع والحالة والتاريخ.
- رفض النطاق الزمني غير الصحيح بدل إرجاع جميع النتائج.
- سجلات الرفض لا تظهر تنفيذ وكيل SQL أو Reporter حين تم رفضها قبل التنفيذ.
- تصدير CSV يقتصر على الحقول الوصفية، وتُعالَج محاولات حقن صيغ جدول البيانات.
- يتم التنقل إلى حدث تدقيق تدريبي فقط إذا كان معرّفه معروفًا ضمن البيانات الثابتة.
- استخدام درج التفاصيل لا ينفذ طلبات شبكة، ولا يكشف الاستدلال الداخلي للنموذج.
- تظهر الصفحة بعرض الهاتف والتابلت والكمبيوتر، ويدعم الدرج لوحة المفاتيح.
