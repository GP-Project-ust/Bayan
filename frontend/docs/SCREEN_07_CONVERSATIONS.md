# الشاشة 07 — سجل المحادثات السابقة (Conversation History)

## 1. الهدف

واجهة مستقلة في مشروع **بيان (Bayan)** على المسار `/conversations`، تُظهر سجلًا توضيحيًا للمحادثات مع البحث والتصفية والترتيب وعرض الرسائل وإدارة الأسماء والمفضلة والحذف بعد التأكيد. هذه الشاشة نموذج أمامي كامل ضمن Next.js مع RTL، وليست خدمة حفظ أو استعادة محادثات حقيقية.

## 2. الحفاظ على الهوية المعتمدة

- لم تتغير ملفات `app/globals.css` و`components/ChatView.tsx` و`components/AdminDashboard.tsx` أو الصور المرجعية.
- تستخدم الشاشة `ChatLayout` و`AppShell` الموجودين في مراحل Design System السابقة؛ أُضيف ملف CSS مستقل `components/conversations/conversations.css`.
- في `Sidebar` تحوّل النص السابق «المحادثات السابقة» إلى رابط `<Link href="/conversations">` دون إضافة CSS أو تغيير ترتيب الأقسام.
- اللون الكحلي `#0A2342` والتركوازي `#00A6B2` والخلفية `#F5F9FD` والخط العربي المعتمد.

| الجزء | الوظائف |

## 4. التخزين وحدود الخصوصية

البيانات الاثنتا عشرة مضمنة في `lib/conversations/conversations.ts` وهي **عينات خيالية** لا تأتي من الجامعة أو الخادم. ملف `localStorage` تحت المفتاح `bayan.demo.conversations.v1` يحتفظ فقط بتغييرات أسماء العينات وقائمة المفضلة والعناصر المحذوفة. الرسائل الجديدة التجريبية تبقى في ذاكرة React الحالية ولا تُحفظ في المتصفح. يؤدي زر الاستعادة إلى محو تعديلات العينة واستعادة الأصل.

يُطبَّق تحقق صارم للقيم المخزنة: التحقق من المعرّفات، حذف المفاتيح غير المتوقعة، والتحقق من طول العناوين وإزالة محارف التحكم. لا تخزن رموز جلسة أو بيانات اعتماد أو معلومات حقيقية.

## 5. صلاحيات العرض

- تعرض العينة فقط سجل المحادثات لمن يملك `chat.ask` في مصفوفة الدور التجريبي.
- تُعرض المصادر فقط لمن يملك `citations.view`.
- يُعرض SQL التوضيحي فقط لمن يملك `sql.inspect`.
- **هذه القيود واجهة عرض فقط**؛ يجب فرض المصادقة، وتصريح الدور، وملكية المحادثة، ونطاق المؤسسة (tenant isolation)، وتصنيف المصادر على الخادم قبل إعادة أية بيانات.

## 6. عقود Backend مقترحة وليست منفّذة

| الطريقة | المسار المقترح | الوصف |
|---|---|---|
| GET | `/api/v1/conversations` | قائمة المحادثات المصرح بها، مع pagination/filter/search |
| GET | `/api/v1/conversations/{id}` | تفاصيل محادثة يملكها المستخدم ضمن المؤسسة |
| PATCH | `/api/v1/conversations/{id}` | تعديل عنوان أو مفضلة المحادثة |
| DELETE | `/api/v1/conversations/{id}` | حذف محادثة ضمن سياسات الاحتفاظ |
| POST | `/api/v1/conversations/{id}/messages` | متابعة المحادثة عبر منسق الوكلاء |

تلك المسارات **اقتراحات تصميمية** ويجب التأكد من دعم Backend لها قبل الربط. لا توجد استدعاءات `fetch` أو SSE حقيقية في هذه الشاشة. يجب عدم إرسال SQL أو مصادر محظورة إلى المتصفح لمن لا يملك صلاحيتها.

## 7. الاختبار

نفّذ بعد تثبيت الحزم:

```bash
npm install
npm run check:conversations
npm run lint
npm run build
npm run dev
npx playwright install chromium
npm run test:e2e
```

- الاختبارات الوحدوية في `tests/contracts/conversations.test.mjs` تختبر البيانات والبحث والعربية والتصفية والفرز والتسمية والمفضلة والحذف والتحقق من التخزين.
- سيناريوهات المتصفح في `tests/e2e/conversations.spec.ts` تغطي البحث والمفضلة وإعادة التسمية والحذف وفتح التفاصيل والمتابعة وعرض 390px.
- يلزم اختبار فعلي عبر المتصفح بعد توفر حزم npm؛ اجتياز فحوص النص والصياغة لا يعني بناء Next.js أو التطابق البصري التام.
