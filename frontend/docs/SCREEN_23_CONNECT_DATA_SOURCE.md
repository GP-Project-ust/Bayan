# الشاشة 23 — ربط مصدر بيانات جديد | Connect Data Source

## النطاق
- **المسار:** `/admin/data-sources/new`.
- **حالة الاستخدام:** UC-05 — إدارة مصادر البيانات وتصنيف الوصول.
- **الدور:** `it_admin` في نموذج العرض فقط، بناء على `sources.manage` في سياسة النظام. لا يُسمح لمسؤول المنصة تلقائيًا بإدارة مصادر المؤسسة.
- **التقنيات:** Next.js App Router + React + TypeScript + CSS مع RTL وتوكنات «بيان» المعتمدة.
- **الحالة:** معالج واجهة تدريبية محلية؛ لا يوجد اتصال بقاعدة بيانات أو شبكة أو مخزن أسرار أو Backend.

## خطوات المعالج الخمس

1. **بيانات المصدر:** الاسم، نوع الموصل (`PostgreSQL`, `Odoo Education`, `MySQL`, `files`, `API`)، الجهة المالكة والغرض.
2. **إعداد الاتصال:** مضيف تدريب ينتهي حصراً بـ `example.invalid`، ومنفذ توضيحي للأنواع غير الملفات. لا يُقدَّم حقل قابل للتحرير لإدخال كلمة مرور أو رمز وصول. وضع الاتصال المخطط هو `read-only`.
3. **التصنيف والأمان:** نطاق البيانات، وتصنيف `public / masked / restricted / blocked`، وإقرار باستخدام بيانات تدريبية وعدم تنفيذ اتصال حقيقي. يؤدي التصنيف المحظور إلى حالة `disabled` بعد الحفظ.
4. **محاكاة التحقق:** فحص الصيغة وصلاحية البيانات والنطاق وعدم التكرار محليًا فقط؛ لا اتصال HTTP ولا اختبار SQL.
5. **المراجعة والحفظ:** عرض جميع الإعدادات الوصفية، وفتح Dialog للتأكيد، وحفظ آمن نسبيًا لبيانات **غير حساسة** ضمن LocalStorage في المفتاح `bayan.demo.sources.created.v1`، أو رسالة خطأ عند فشل التخزين.

يُحدَّد الحد الأقصى بمقدار 15 مصدرًا تدريبيًا إضافيًا لكل متصفح. تُفحَص المدخلات المعادة من `localStorage` وتُعاد صياغة السجلات باستخدام قائمة حقول مسموحة، دون الاحتفاظ بخصائص إضافية. لا يُسمح بمضيف حقيقي أو عنوان IP أو اسم مستخدم أو كلمة مرور أو مفتاح API.

## التكامل مع الشاشة 22

تعرض `/admin/data-sources` المصدر التدريبي المضاف مع رمز `SRC-DEMO-...` وحالة `pending` (أو `disabled` للمحظور) عند العودة إلى القائمة. تُقرأ البيانات الوصفية من المخزن نفسه، بينما يستمر عمل المصادر الثمانية الأصلية وحالة تعطيلها التجريبية بصورة مستقلة. لا يُمكن تغيير حالة المصادر المضافة من الشاشة 22 لأن ذلك لم يُنفذ ضمن دورة إدارية حقيقية.

## ضوابط الأمان المطلوبة قبل الإنتاج

- التحقق الحقيقي من الهوية والدور ونطاق `tenant_id` داخل FastAPI لكل عملية.
- استقبال بيانات الاعتماد حصراً عبر TLS إلى Backend وحفظها بمخزن أسرار؛ عدم إرسالها إلى السجلات أو المتصفح أو LocalStorage.
- الاتصال باستخدام مستخدم **قراءة فقط** مع أقل قدر من الأذونات وإجراء اختبارات اتصال معزولة ومحدودة زمنياً، مع حماية من SSRF ورفض الشبكات الداخلية والوجهات غير المصرح بها.
- اعتماد تصنيف البيانات/الأعمدة والعروض الذكية قبل جعل المصدر قابلًا للاستعلام.
- كتابة سجل تدقيق لكل محاولة وإدارة حالة المصدر، مع عرض نتائج آمنة لا تكشف كلمات المرور.
- إدارة حالات عدم نجاح الاتصال وإلغاء العمليات وإعادة المحاولة بشكل محدود ومراقب.

## عقود Backend المقترحة — **غير موجودة في هذه الواجهة**

| الطريقة | المسار المقترح | الغرض |
|---|---|---|
| `POST` | `/api/data-sources` | إنشاء سجل وصف المصدر داخل المؤسسة بعد الصلاحية والتحقق |
| `POST` | `/api/data-sources/:id/credentials` | إرسال بيانات الاعتماد إلى مخزن أسرار عبر مسار آمن |
| `POST` | `/api/data-sources/:id/test` | اختبار الاتصال من الخادم ضمن حدود أمان |
| `GET` | `/api/data-sources` | استرجاع المصادر المصرح بها حسب المؤسسة |
| `GET` | `/api/audit` | مراجعة آثار إدارة المصادر بحسب الصلاحية |

هذه مجرد اقتراحات لتنفيذ لاحق، ويجب مراجعتها مع مسارات FastAPI الفعلية وعدم افتراض وجودها الآن.

## معايير القبول

1. تعمل خطوات المعالج الخمس وتحافظ على البيانات عند التنقل للخلف.
2. لا تسمح بالانتقال عند وجود أخطاء في الحقول، أو عنوان مضيف غير تجريبي، أو عدم تأكيد الإقرار.
3. لا تسمح بالحفظ قبل تنفيذ محاكاة التحقق.
4. لا تخزّن كلمات مرور أو رموز وصول أو مفاتيح؛ النطاقات وهمية.
5. تعرض حالة نجاح صريحة توضح أن الحفظ محلي فقط.
6. يظهر السجل الوصفي المحفوظ في قائمة `/admin/data-sources`.
7. يمنع دور غير مسؤول تقنية المعلومات الوصول إلى معالج الربط في نموذج العرض.
8. تبقى ملفات الهوية المرجعية للمحادثة ولوحة الإدارة دون تعديل.
