# بيان — تقرير جودة الشاشة 35

## فحوص ناجحة

- `npm run check:model-providers`: اجتاز فحص بنية الشاشة ومرجعيات التصميم، وفحص صياغة 202 ملف TypeScript/TSX، ونجحت 11 حالة اختبار خاصة بمزودي النماذج.
- `node --test tests/contracts/*.test.mjs`: نجحت **275 حالة اختبار عقود** في المشروع كاملًا؛ بلا إخفاقات.
- `npm run check:onboarding-history`: نجحت 14 حالة اختبار للتوافق مع الشاشة السابقة.
- فحص بصمات SHA-256 للملفات المرجعية: الصور، وصفحات المحادثة والإدارة، وملف CSS الأصلي، وSidebar، ومصفوفة RBAC المركزية كلها دون تعديل.
- توليد مخطط Graphviz وMermaid للشاشة الخامسة والثلاثين.

## اختبارات لم تُنجز

- `npm run build` أظهر `next: not found` لأن تبعيات Next.js غير مثبتة في بيئة التنفيذ. **لم ينجح بناء الإنتاج ولم نجر فحص TypeScript الكامل بمكتبات React/Next المثبتة.**
- اختبارات Playwright للمتصفح لم تُشغّل؛ الملفات جاهزة للتشغيل على جهاز المطور بعد `npm install` و`npx playwright install chromium`.
- لم يتم فحص التطابق البصري داخل التطبيق أثناء التشغيل. لذلك لا يُعلن أن الشاشة جاهزة للإنتاج.

## إجراءات القبول المحلية المقترحة

1. تثبيت الحزم، تشغيل `npm run lint` ثم `npm run build` ومعالجة أي أخطاء.
2. فتح `/platform/models` والتحقق من اتجاه RTL وسلامة القائمة والألوان.
3. الاختبار بعرض 390 و768 و1280 بكسل.
4. تجربة جميع المرشحات ومعاينة تفاصيل مزود ونموذج.
5. حفظ مسودة RPM ثم إعادة تحميل الصفحة ثم استعادة القيم الأصلية.
6. اختيار دور الموظف والتأكد من عرض منع الوصول.
7. فتح فحص الجاهزية وملاحظة عبارة «صفر طلبات شبكة»، والتحقق من عدم خروج طلبات إلى مزودي نماذج.
8. تنزيل CSV والتحقق من عدم وجود معلومات اعتماد أو حقول حساسة.
9. عند الربط مع FastAPI يجب تنفيذ RBAC الحقيقي ومخزن الأسرار والتدقيق والحدود الفعلية للاستخدام.
