# الشاشة 31 — تفاصيل مسار تنفيذ الوكلاء (Agent Trace Details)

**المسار:** `/admin/agent-traces/details?id=TRACE-DEMO-0007`  
**حالة التنفيذ:** واجهة تدريبية Frontend، غير متصلة بـFastAPI أو LangGraph.  
**المرجع الوظيفي:** UC-06، تتبع العمليات والرقابة على تنفيذ الوكلاء.  
**الهوية المعتمدة:** ألوان بيان (كحلي `#0A2342`، تركوازي `#00A6B2`، خلفية فاتحة، عربية RTL)، باستخدام `AdminLayout` ومكتبة المكونات السابقة.

## الهدف

عرض تفاصيل المسار المسموح بمراجعته من ناحية الوكلاء المشاركين، ومدة المعالجة، والنتيجة التشغيلية، والإحالة إلى حدث التدقيق المرتبط إن وُجد. لا تعرض الشاشة **سلسلة التفكير الداخلية للنموذج** أو نص السؤال الخام أو SQL التنفيذي أو مقاطع المستندات الخاصة أو الأسرار.

## مكونات الواجهة

1. **بطاقة المسار**: الوصف التدريبي، معرّف التتبع، الحالة، وقت البدء، ونسخ مرجع وصفي آمن.
2. **مؤشرات عامة**: المدة، عدد الخطوات، الخطوات الناجحة، والرافضة/الفاشلة.
3. **تبويب نظرة عامة**: بيانات التشغيل الأساسية والوكلاء المشاركون، باستبعاد الخطوات المتجاوزة غير المنفذة من عداد الوكلاء المشاركين.
4. **تبويب الخط الزمني**: تسلسل خطي للخطوات مع إمكانية التوسيع والطي وقياس مدة كل خطوة من البيانات الاصطناعية الموجودة. المدّد التراكمية *محسوبة لتوضيح ترتيب الخطوات فقط*، وليست أوقات بدء مستقلة أو جدول تنفيذ متوازٍ حقيقي.
5. **تبويب نتيجة التنفيذ**: نجاح، فشل، رفض، أو حالة جارية ثابتة، مع إحصاء الخطوات وتوضيح حدود البيانات.
6. **تبويب الخصوصية**: توضيح العزل المؤسسي وقواعد حجب المعلومات الحساسة.
7. **التنقل**: العودة لقائمة التتبعات، والسابق/التالي ضمن 8 عينات موجودة، ورابط حدث التدقيق في الحالات التي تحتوي على مرجع مطابق لبيانات شاشة التدقيق.

## المسارات المرتبطة

- `/admin/agent-traces`: قائمة التتبعات (الشاشة 30)، ومنها فتح الصفحة الكاملة.
- `/admin/audit`: سجل التدقيق (الشاشة 28).
- `/admin/audit/details?id=AUD-DEMO-007`: حدث تدقيق تدريبي مطابق لتتبع `TRACE-DEMO-0007`.

## نماذج التجربة

| المسار | الحالة |
|---|---|
| `?id=TRACE-DEMO-0007` | مسار RAG ناجح ومرتبط بحدث تدقيق |
| `?id=TRACE-DEMO-0012` | فشل في خطوة Analyst وتجاوز Reporter |
| `?id=TRACE-DEMO-0013` | رفض مبكر قبل تشغيل SQL |
| `?id=TRACE-DEMO-0105` | حالة `running` ثابتة؛ لا توجد مهمة في الخلفية |
| `?id=TRACE-DEMO-9999` | معرّف صحيح الصيغة لكن لا ينتمي للبيانات التجريبية |
| `?id=INVALID` | معرّف غير صالح |
| بدون `id` | لا يوجد معرّف محدد |

## سياسة الوصول

- يظهر المحتوى لمسؤول تقنية المعلومات المؤسسي عبر صلاحية `traces.view` في **محاكاة الواجهة فقط**.
- تمنع المحاكاة الموظف والمدير ومسؤول المنصة من قراءة مسارات المؤسسة. لا يكتسب مسؤول المنصة صلاحية لبيانات المؤسسات تلقائيًا.
- يتطلب نظام الإنتاج مصادقة، والتحقق في الخادم من دور المستخدم و`tenant_id`، وإخفاء محتوى السجلات عند إرجاع نتائج API.

## فصل التجربة عن الإنتاج

- لا تستدعي الشاشة `fetch` أو WebSocket أو SSE، ولا تعتمد على تنفيذ مباشر للوكلاء.
- البيانات تأتي من `lib/agent-traces/traces.ts`، وهي **ثمانية مسارات اصطناعية ثابتة** مشتركة مع الشاشة 30.
- **لا يوجد تشغيل أو توقف حقيقي**: مثال `running` مجرد حالة توضيحية.
- لا تخزّن الشاشة بيانات حساسة محليًا. نسخ المرجع يقتصر على معلومات وصفية تجريبية.
- لا يتم إنشاء سجل تدقيق غير موجود بالاستناد إلى معرّف مسار فقط.

## عقود API مقترحة مستقبلًا (غير منفذة)

| العملية | API مقترح | متطلبات الأمان |
|---|---|---|
| استعراض مسار | `GET /api/v1/admin/agent-traces/{trace_id}` | Session/Auth + `traces.view` + tenant-scoping + redaction |
| استعراض حدث التدقيق المرتبط | `GET /api/v1/admin/audit/{event_id}` | تدقيق الصلاحيات والنطاق وإخفاء الحقول |

> هذه مسارات تصميم مقترحة وليست API متاحة حاليًا؛ ينبغي مطابقتها مع Backend قبل التطوير.

## اختبارات القبول

- فتح الصفحة مباشرة بمعرّف موجود أو عبر رابط الشاشة 30.
- عرض واجهة الرفض للأدوار التي لا تمتلك `traces.view`، دون كشف محتوى التفاصيل.
- التعامل مع المعرّف المفقود وغير الصالح وغير الموجود برسالة واضحة.
- مطابقة حالة كل خطوة ومدتها مع بيانات العينة، وعدم اختلاق مدد عند `running` و`skipped`.
- عدم إظهار استعلام SQL أو نصوص خاصة أو أسرار أو سلسلة التفكير الداخلية.
- ربط مثال التدقيق الذي يحمل معرّفًا مطابقًا فقط.
- عرض مناسب للكمبيوتر والتابلت والهاتف، مع استخدام Tab وEscape والتركيز المرئي.
- عدم تغيير ملفات الصور وCSS المرجعية للواجهات الأصلية.
