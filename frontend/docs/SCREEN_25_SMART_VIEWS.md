# الشاشة 25 — إدارة العروض الذكية (Smart Views Management)

**نظام بيان | Next.js + TypeScript | المسار `/admin/smart-views`**

## الهدف
تقديم واجهة موحدة لإدارة كتالوج العروض الذكية (Smart Views) المرتبطة بمصادر بيانات المؤسسة، ومراجعة الحقول المسموح بها والتصنيف الأمني وحالة كل عرض، قبل اعتماد تكامل SQL الحقيقي مع FastAPI.

## الحدود: تصميم تجريبي، لا تنفيذ حقيقي
- الأمثلة الأربعة `SV-DEMO-01` إلى `SV-DEMO-04` مشتقة من بيانات العروض التوضيحية الموجودة بالفعل في `lib/data-sources/details.ts` للشاشة 24.
- المقترحات الثلاثة `SV-PROPOSAL-01` إلى `SV-PROPOSAL-03` **مسودات غير منشورة** وليست عروضًا موجودة في قاعدة البيانات.
- لا يتم إنشاء SQL أو تشغيله أو فحص مخطط قاعدة البيانات. لا اتصال بـPostgreSQL أو Odoo أو FastAPI أو Qdrant.
- لا يُعرض أي حقل محظور، ولا كلمات مرور أو رموز أو بيانات طلاب فعلية.
- الحالة النشطة لا تعني أن هناك View فعليًا؛ النشط مجرد إشارة واجهة تعليمية.

## العناصر الأساسية
1. بطاقات مؤشرات: الإجمالي والنشط والمسودات والمقيّد/المقنّع.
2. البحث العربي المطبّع؛ وتصنيف النتائج حسب المصدر والحالة والتصنيف ونوع السجل.
3. جدول قابل للتمرير على الهاتف: العرض، المصدر، الحقول، الحالة، مستوى الوصول، والإجراءات.
4. درج يعرض بطاقة العرض والحقول ومصدره مع نسخ وصف محدود (JSON بلا أسرار).
5. تغيير حالة `SV-DEMO-01` وحده بين نشط وموقوف في `localStorage`، وبنافذة تأكيد.
6. رابط إلى `/admin/data-sources/details?id=...`؛ ورابط إلى شاشة إنشاء عرض `/admin/smart-views/new` التي تأتي في المرحلة التالية.
7. إظهار رفض الوصول للأدوار غير المخوّلة في سياسة العرض المركزية.

## حالات النجاح والخطأ
- البحث لا يُرجع نتائج: حالة فارغة وزر مسح المرشحات.
- غياب صلاحية `smartviews.manage`: منع وصول توضيحي.
- المصدر المحظور: لا تنشأ له عروض ولا تظهر حقوله.
- المصدر المعطّل: لا يسمح بتغيير حالته التوضيحية إلى نشط.
- فشل التخزين المحلي: رسالة خطأ وعدم الادعاء بحفظ التغيير.
- مفتاح تخزين غير صالح: يُهمل عند الاستعادة.

## عقد Backend المستقبلي (مقترح وليس منفذًا)
- `GET /api/v1/smart-views` — جلب العروض المسموح بها مع نطاق المؤسسة.
- `GET /api/v1/smart-views/{id}` — تفاصيل العرض المصرّح به.
- `POST /api/v1/smart-views` — إنشاء تعريف للقراءة فقط بعد التحقق والأمن.
- `PATCH /api/v1/smart-views/{id}` — مراجعة واعتماد التعريف بعد تفويض مسؤول المؤسسة.
- `POST /api/v1/smart-views/{id}/validate` — اختبار آمن من الخادم فقط دون عبارات DDL/DML.
- `GET /api/v1/audit` — سجل عمليات الاعتماد والتغيير.

لا تعتبر هذه المسارات موجودة في Backend حتى يتحقق الفريق من التنفيذ. حماية الإنتاج تتطلب **المصادقة، عزل المؤسسات، تقييد أسماء الحقول والجداول، استعلامات قراءة فقط، حدود التنفيذ، تصفية النتائج، وتدقيق كل عملية** داخل الخادم.

## التشغيل والاختبار
```bash
npm install
npm run check:smart-views
npm run lint
npm run build
npm run dev
```
زيارة: `http://localhost:3000/admin/smart-views`.

`check:smart-views` فحص بنيوي/عقود ولا يحل محل بناء Next.js أو تشغيل اختبارات Playwright. عند استحالة الوصول إلى سجل npm يجب تسجيل هذه الاختبارات كـ«لم تُنفذ».
