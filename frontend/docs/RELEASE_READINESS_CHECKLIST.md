# بوابة قبول إصدار نظام «بيان» — Release Gate

**قرار الإصدار الافتراضي: NOT READY FOR PRODUCTION.** هذه قائمة تحقق مستقبلية وليست حالة تنفيذ معتمدة.

## مرحلة استقرار Design System

- [x] توثيق Design Tokens وصفحات المعاينة للمراحل السبع.
- [x] إنشاء مكتبة مكونات React وإضافة هياكل الصفحات.
- [x] إعداد سجل قبول 42 شاشة و7 حالات استخدام + حالات عرض وأمن ووصول.
- [x] توفير فحوص بنيوية لا تعتمد على npm.
- [ ] نجاح `npm install` و`npm run lint` و`npm run build` في بيئة المشروع.
- [ ] نجاح مجموعة اختبارات Playwright عبر العرض desktop/tablet/mobile.
- [ ] توقيع مراجعة بصرية يدوية للشاشتين المعتمدتين.
- [ ] مراجعة وصول keyboard + screenreader + contrast + zoom من مختبر مستقل.

## التشغيل والإنتاج

- [ ] بناء وربط الشاشات الفرعية الـ40 بوظائف فعلية، لا نماذج UX مشتركة فقط.
- [ ] ربط Auth وAPI وSSE والعمليات الحساسة بخادم حقيقي.
- [ ] اعتماد نموذج RBAC وتطبيقه في Backend وقاعدة البيانات وعزل المؤسسات.
- [ ] اختبارات منع SQL غير آمن وترشيح مستندات RAG وحماية سجلات التدقيق.
- [ ] اختبار أخطاء 400/401/403/429/500 وفقد الشبكة مع سيناريوهات Retry واضحة.
- [ ] اختبارات حركة بيانات الإنتاج وقيود التصدير PDF/XLSX وفق الصيغ الفعلية.
- [ ] اختبار حفظ الحالات والتعامل مع الأجهزة المساندة والحوادث والتحميل.
- [ ] الحصول على موافقة الفريق الأمني والجهة المالكة للمنتج.

## قواعد القرار

1. لا تُعلن جاهزية الإنتاج عند وجود Fail في اختبارات P0.
2. لا تعتبر الاختبارات المحجوبة أو غير المنفذة ناجحة.
3. لا تعتمد على فحص TypeScript Syntax أو CSS كدليل على مطابقة UX الفعلية.
4. لا يعتمد الأمن إلا بعد فحوص خادم وجلسة ومؤسسة، ولا يكفي عرض RBAC في المتصفح.
5. يُرفق ملف QA JSON من `/design-system/quality` بالنسخة المرشحة للإصدار مع سجل التغييرات.
