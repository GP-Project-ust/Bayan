# مصفوفة قبول الشاشات والتدفقات — بيان

**الحالة:** خطة فحص وليست نتائج اختبارات منفذة. القيم الافتراضية لكل حالة «لم يُختبر».

المصدر: `lib/screen-catalog.json` (42 شاشة) + المتطلبات الوظيفية UC-01..UC-07 وتوقعات الجودة.

## أدوار المختبرين والأدلة المقبولة

- منفّذ الاختبار: عضو QA مستقل عن مؤلف الواجهة متى أمكن.
- لكل فحص: تاريخ التنفيذ، الجهاز، المتصفح، الدور التجريبي/الحقيقي، النتيجة، ورابط صورة أو سجل الخطأ.
- **Pass:** جميع شروط الفحص المنطبقة محققة؛ **Fail:** خلل مثبت؛ **Blocked:** اعتماد/خدمة مفقودة؛ **Not run:** لم يبدأ.
- اختبارات الحماية الحقيقية تبقى Blocked إلى حين ربط الخادم وتهيئة حسابات فعلية.

## إجراء الاختبار اليدوي

1. شغّل Next.js وافتح `/design-system/quality`.
2. حدد التصنيف أو المسار، وافتح «تفاصيل» حالة الفحص.
3. نفّذ شروط القبول على الأجهزة والأدوار اللازمة؛ لا تُعلن Pass بناء على نظرة بصرية فقط.
4. سجل المختبر والنتيجة والملاحظات؛ تُحفظ محليًا في المتصفح فقط.
5. صدّر JSON من صفحة الجودة وأرفقه بمراجعة الإصدار.
6. لا يُعتمد الإصدار إذا بقي أي اختبار P0 فاشلًا، أو لم تُختبر الحالات الأمنية المطلوبة فعليًا.
