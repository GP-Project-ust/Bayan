# بيان — نظام التصميم | المرحلة 2 من 7

## الهدف
تحويل رموز الهوية البصرية المعتمدة من المرحلة الأولى إلى مكتبة مكونات واجهات حقيقية قابلة لإعادة الاستخدام داخل Next.js / TypeScript، مع إبقاء التصميمين الأصليين للمحادثة والإدارة دون تعديل.

## ما جرى تنفيذه

| المكون | الملف | الوظائف الأساسية |
|---|---|---|
| Button | `components/ui/Button.tsx` | 5 أنواع، 3 أحجام، تحميل، تعطيل، أيقونات، عرض كامل |
| Input | `components/ui/Input.tsx` | عنوان، نص مساعد، حالة خطأ، أيقونة، تركيز، `dir=ltr` عند الحاجة |
| Select | `components/ui/Select.tsx` | خيارات، عنوان، خطأ، دعم لوحة المفاتيح |
| Textarea | `components/ui/Textarea.tsx` | إدخال متعدد الأسطر، عنوان، خطأ، وصف |
| Card | `components/ui/Card.tsx` | ترويسة ومحتوى وتذييل وإجراء اختياري |
| Badge | `components/ui/Badge.tsx` | خمس حالات: محايد، نجاح، تحذير، خطأ، معلومة |
| DataTable | `components/ui/DataTable.tsx` | أعمدة typed، صفوف typed، حالة فارغة، تمرير أفقي |
| Dialog | `components/ui/Dialog.tsx` | نافذة تأكيد مع إغلاق Escape والنقر على الخلفية وحبس التركيز |
| Drawer | `components/ui/Drawer.tsx` | درج جانبي من بداية/نهاية الاتجاه مع إدارة التركيز |
| Toast | `components/ui/Toast.tsx` | أربع حالات تنبيه مع إعلان مساعد وإغلاق |

## الصفحة الجديدة

`http://localhost:3000/design-system/components`

تحتوي على 6 مناطق: الأزرار، الحقول، البطاقات والشارات، الجدول، النوافذ والأدراج، والتنبيهات. وفيها محاكاة محلية لإضافة مستخدم والبحث في جدول وعرض رسالة خطأ؛ لا تتصل بخادم حقيقي.

## مثال استخدام

```tsx
"use client";
import { Button, Input, Card, Badge } from "@/components/ui";
import "@/components/ui/ui.css";

export function Sample() {
  return (
    <Card title="إدارة المستخدمين" description="واجهة توضيحية">
      <Input label="البريد الإلكتروني" type="email" dir="ltr" placeholder="name@example.org" />
      <Badge tone="success">نشط</Badge>
      <Button variant="primary">حفظ</Button>
    </Card>
  );
}
```

**ملاحظة:** استيراد `ui.css` في مستوى layout أو الصفحة التي تستخدم المكونات يكفي. لا داعي لاستيراده من كل مكون.

## القرارات الهندسية

- تبدأ جميع أسماء CSS الجديدة بـ`bui-`، ولا تعدّل `.app-layout` أو `.admin-layout` أو `.chat-body`.
- تستخدم المكونات المتغيرات `--bayan-*` الخاصة بالمرحلة الأولى.
- تدعم حقول الإدخال النصوص العربية وRTL، مع الحفاظ على البريد وSQL باتجاه LTR.
- لا تحتوي المكونات على خدمات API ولا وصول إلى بيانات حساسة.
- واجهات اختيار المستخدم والأدوار محاكاة فقط؛ تطبيق RBAC الحقيقي مسؤولية الخادم.
- استخدام `forwardRef` للحقول والأزرار لتسهيل التكامل مع المكتبات وأدوات الاختبار.
- يعتمد Dialog وDrawer على `role=dialog` و`aria-modal` وحبس التركيز في المحتوى ونقل التركيز بعد الإغلاق. يجب اختباره فعليًا بالمتصفح وقارئ الشاشة قبل الاستخدام الإنتاجي.
- مكتبة CSS بلا تبعية خارجية جديدة ولا تحتاج إلى Tailwind؛ تظل الحزم وفق `package.json` السابق.

## ما لم يُنفذ بعد

1. نقل واجهتي المحادثة والإدارة القديمتين إلى المكونات الجديدة؛ حافظنا على مظهرهما الأصلي وعدم كسر توافقهما.
2. توثيق Storybook واختبارات الوحدة واختبارات E2E؛ هذه ضمن مرحلة الاختبارات والتوثيق.
3. المصادقة وRBAC والاتصال بمسارات Backend والتصدير الحقيقي.
4. التحقق من البناء والإظهار النهائي بسبب تعذر تنزيل الحزم في بيئة تجهيز المشروع.
