# الشاشة 11 — عارض المستندات والمصادر (Document Viewer)

**نظام بيان · Next.js 15 / React 19 / TypeScript · واجهة عربية RTL · نموذج تفاعلي تجريبي**

## 1. الهدف

صفحة مستقلة لعرض البيانات الوصفية لأي مستند في مكتبة «بيان»، والتنقل بين أرقام الصفحات، وإظهار المقاطع المجمّعة وفق اسم المستند ورقم الصفحة، ونسخ استشهاد توضيحي، والعودة إلى المكتبة أو البحث الدلالي. واجهة الشاشة تحقق الجزء البصري المقترح من UC-02 (البحث في المستندات واللوائح) دون ادعاء تقديم استرجاع حقيقي أو ملف PDF أصلي.

## 2. الحدود الحالية — أساسي

**لا يحتوي المشروع على ملفات PDF فعلية للمستندات التدريبية التسعة.** المحتوى والجهات والصفحات والمقتطفات أمثلة خيالية، متطابقة المعرّفات مع الشاشة 09 (البحث الدلالي) والشاشة 10 (مكتبة المستندات). لذلك لا يُنشئ العارض «صفحات» وهمية مملوءة بنصوص رسمية، بل:

- الصفحة التي لها مقطع بيانات تجريبية: تعرض المقطع داخل صفحة تصميمية مع عبارة تحذيرية صريحة.
- الصفحة التي لا تحتوي على مقطع: تعرض حالة «لا تتوفر بيانات نصية لهذه الصفحة».
- مستند غير مفهرس أو لم تُسترجع له مقتطفات: يتوفر عارض وصفي دون اختلاق نص.
- زر عرض PDF الأصلي **معطّل**، لأن الملفات غير موجودة.
- لا يوجد `fetch` أو إرسال ملفات أو فهرسة حقيقية. حالة الصلاحيات داخل الواجهة فقط.

## 3. المسار وروابط التكامل

| المسار | الوظيفة |
|---|---|
| `/sources` | مكتبة المستندات (الشاشة 10) |
| `/semantic-search` | بحث دلالي تجريبي (الشاشة 09) |
| `/sources/document` | عارض المستند (الشاشة 11) |
| `/sources/document?doc=doc-academic&page=12&snippet=rag-001` | تجربة المقطع في الصفحة 12 |
| `/sources/document?doc=doc-academic&page=13` | تجربة صفحة بلا مقطع |
| `/sources/document?doc=doc-policy-draft&page=1` | تجربة مستند غير مفهرس |
| `/sources/document?doc=doc-invalid` | مثال معرّف مستند غير موجود |

عند فتح `/sources/document` دون معاملات، يعرض النظام المثال الأول من مكتبة التدريب. توجد روابط جديدة «فتح العارض» في بطاقات المكتبة وقائمتها ودرج تفاصيلها، و«عرض الصفحة» في نتائج البحث الدلالي ودرج الاستشهاد. بُقي مسار الكتالوج القديم مستخدمًا، وأُزيل تكراره من توليد مسارات الصفحة الشاملة `catch-all`.

## 5. نموذج البيانات وأمان الروابط

تستخدم `lib/document-viewer/viewer.ts` نموذج `LibraryDocument` الموجود في `lib/document-library/library.ts`، والمقتطفات `Snippet` من `lib/semantic-search/search.ts`. لا يوجد مصدر ثانٍ للمحتوى أو صفحات مصطنعة جديدة.

- يتحقق `getDemoDocument` من صيغة المعرّف ويبحث في قائمة معرّفات معروفة فقط؛ لا يفتح مسارًا عشوائيًا على القرص.
- يتحقق `parseDocumentPage` من أن رقم الصفحة عدد صحيح موجب ضمن الحد المسجل للمستند.
- لا يقبل العارض طلب مقتطف `snippet` إلا إذا كان تابعًا للمستند والصفحة.
- ينشئ `viewerHref` روابط قابلة للنسخ والمشاركة؛ لا تحمل محتوى المستند.
- `getPageCitation` يعيد `null` إذا لم تتوفر عينة مقطع في الصفحة، فيُعطَّل زر الاستشهاد.

## 6. صلاحيات العرض

يعتمد النموذج نفس أدوار بيان الأربعة. يُسمح للموظف والمدير ومسؤول تقنية المعلومات بعرض نماذج المستندات والاستشهادات؛ لا يُمنح مسؤول المنصة صلاحية تلقائية لمحتوى المؤسسة. لا يمثل محدد الدور مصادقة فعلية، ولا يجوز حماية الملفات الحقيقية اعتمادًا عليه.

في التطبيق الحقيقي يجب أن يتحقق Backend من هوية المستخدم وتبعيتِه للمؤسسة وتصنيف المستند وصلاحيات الدور **قبل** تسليم محتوى المستند أو رابط ملف PDF أو مقتطف قابل للنسخ. يجب أن تكون الروابط الموقّعة محددة الصلاحية ومؤقتة عند الحاجة، وأن يسجل النظام الوصول والتصدير وفق السياسة المعتمدة.

## 7. التكامل المستقبلي المقترح (غير منفذ)

| الطريقة | مسار API مقترح فقط | الهدف |
|---|---|---|
| `GET` | `/api/v1/documents/{id}` | بيانات وصفية بعد التحقق من الصلاحيات |
| `GET` | `/api/v1/documents/{id}/pages/{page}` | نص/صورة الصفحة المصرح بها أو حالة عدم التوفر |
| `GET` | `/api/v1/documents/{id}/snippets?page=N` | مقتطفات موثوقة بمصدر ورقم صفحة مطابقين |
| `GET` | `/api/v1/documents/{id}/file` | رابط PDF مؤقت أو بث آمن بعد RBAC/tenant checks |

هذه **اقتراحات تصميمية** وليست مسارات موجودة أو منفذة. يلزم الاتفاق على عقود FastAPI مع فريق الـBackend قبل توصيل العارض. لا يعرض العارض في نسخته الحالية أي رمز وصول أو مستند خاص.

## 8. فحوص التسليم والاختبارات

```bash
npm install
npm run check:document-viewer
npm run lint
npm run build
npm run dev
# على جهاز مثبت عليه Playwright:
npx playwright install chromium
npm run test:e2e -- --grep "screen 11"
```

تغطي اختبارات Node: المعرّفات، ومعالجة أرقام الصفحات، والروابط العميقة، وصحة تبعية المقاطع للمستند، وحدود التنقل، وعدم اختلاق مقتطفات لمستندات بلا فهرسة. وتغطي Playwright سيناريوهات التنقل والتباين بين المقتطف والصفحة الفارغة والصلاحيات والأجهزة الصغيرة. **نجاح فحص الصياغة والعقود لا يثبت نجاح بناء Next.js أو مطابقة التصميم داخل المتصفح**.
