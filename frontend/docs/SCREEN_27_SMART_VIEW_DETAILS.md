# الشاشة 27 — تفاصيل العرض الذكي واختباره | BAYAN

## المسار

`/admin/smart-views/details?id=SV-DEMO-01`

الشاشة متصلة بقائمة العروض الذكية `/admin/smart-views`، وبالمسودات التي تُنشأ من `/admin/smart-views/new` عبر التخزين المحلي المشترك `bayan.demo.smartviews.drafts.v1`.

## أقسام الشاشة

1. **نظرة عامة:** اسم العرض والجهة ونطاق الوصول والمصدر وحالة النشر الافتراضية.
2. **الحقول والتعريف:** جدول الحقول وبياناتها الوصفية، ومعاينة JSON للقراءة فقط. يمكن إظهار SQL تصوري غير منفذ للمسودات المحلية المعتمدة على نماذج PostgreSQL/MySQL التدريبية فقط؛ ولا تظهر أوامر SQL للأمثلة غير المؤكدة.
3. **التصنيف والوصول:** صلاحية إدارة المؤسسة، والتصنيف الوصفي للمصدر والعرض، والتنبيه عند اختلاف مستوى الحساسية.
4. **الفحص المحلي:** اختبار مصدر البيانات وبنية التعريف وتصنيف الوصول، وعرض صفوف اصطناعية من قائمة قيم ثابتة *فقط عند اجتياز القيود*.

## قواعد الأمان

- الدور التجريبي المصرّح له: `it_admin` عبر `smartviews.manage`. يمنع العرض لبقية الأدوار، بما فيها مسؤول المنصة.
- جميع البيانات والتصنيفات التدريبية مستمدة من أمثلة موجودة في المشروع السابق. **لا يوجد استكشاف فعلي لمخطط قاعدة البيانات**.
- معرّف العرض يقبل فقط الأنماط المعروفة `SV-DEMO-01..04` و`SV-PROPOSAL-01..03` أو مسودات `SV-DRAFT-xxxxxxxx` المُحقَّق منها.
- تُقرأ المسودات من التخزين المحلي بعد تطبيق `restoreLocalDrafts` الذي يتحقق من الحقول والتصنيف. أي مصدر محظور أو معطل يمنع المعاينة.
- النص المنسوخ لا يحتوي بيانات تسجيل دخول أو سجلات أشخاص أو SQL منفذ.
- نتيجة الفحص وصفية ومحلية ولا تتصل بخادم. يُمنع عرض صفوف حين لا يُقبل مستوى التصنيف أو تكون الحقول غير معروفة.
- لا توجد وظيفة نشر أو تنفيذ استعلام SQL أو اتصال PostgreSQL/Odoo أو تغيير صلاحيات حقيقي.

## سلوك حالات الاختبار

- `?id=SV-DEMO-01`: مثال توضيحي؛ المصدر مقيّد والتصنيف الوصفي للعرض أقل منه، لذلك تظهر نتيجة **تحتاج مراجعة** دون صفوف.
- `?id=SV-DEMO-04`: مثال لمصدر API؛ JSON وصفي، لا SQL.
- `?id=SV-DRAFT-abc12345`: يعمل فقط إن كانت هذه المسودة موجودة فعليًا في متصفح المستخدم بعد إنشائها من الشاشة 26.
- `?id=SV-DEMO-99` أو غياب ID: حالة غير موجود/رابط غير صالح.
- تغيير الدور إلى موظف: منع الوصول داخل محاكاة واجهة المستخدم.

## ربط Backend المستقبلي (مقترح، غير منفذ)

- `GET /api/smart-views/{id}`: تعريف العرض بعد المصادقة والتحقق من المؤسسة والصلاحيات.
- `POST /api/smart-views/{id}/validate`: طلب تدقيق أمني/بنيوي على الخادم دون تنفيذ SQL حر.
- `GET /api/smart-views/{id}/audit`: سجل تدقيق مختصر مصرح به.
- لا تُخزن كلمات المرور في المتصفح؛ ويجب فرض RBAC/RLS وعزل المؤسسة في Backend.

**هذه المسارات عقود مقترحة وليست API موجودة بالفعل.**

## الاختبارات

`npm run check:smart-view-details` لفحوص الكود والمنطق دون شبكة. كما أُضيفت اختبارات Playwright في `tests/e2e/smart-view-details.spec.ts` لتعمل بعد تثبيت الحزم وتشغيل التطبيق محليًا.
