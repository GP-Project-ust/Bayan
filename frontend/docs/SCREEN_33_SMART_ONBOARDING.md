# الشاشة 33 — معالج التهيئة الذكية للمؤسسات (Smart Onboarding Wizard)

**المسار:** `/platform/onboarding`  
**المجموعة:** إدارة المنصة  
**المتطلبات الأساسية:** UC-07 وFR-28 في كتالوج الشاشات  
**الدور التجريبي:** مسؤول المنصة `platform_admin` — صلاحية `onboarding.run`  
**الحالة:** واجهة Next.js تفاعلية بالمكونات الموجودة؛ لا يوجد تكامل فعلي مع FastAPI أو Qdrant أو PostgreSQL أو Odoo.

## الهدف

توحيد المراحل المتصورة لتهيئة مؤسسة مستفيدة من بيان في **تجربة آمنة غير متصلة بالشبكة**. تُعرض أسماء مؤسسات ومخططات وعروض وملفات اصطناعية فقط، ولا يُطلب إدخال كلمات مرور أو أسرار أو بيانات مستخدمين.

## الخطوات الست

| المرحلة | البيانات / الإجراء | شرط الانتقال | حد التنفيذ الحالي |
|---|---|---|---|
| 1. المؤسسة | اختيار مؤسسة تجريبية في مرحلة التهيئة أو تعريف مؤسسة جديدة اصطناعية | معرّف معروف أو اسم صالح ورمز لاتيني | لا تُنشأ مؤسسة في قاعدة البيانات |
| 2. مصادر البيانات | اختيار PostgreSQL أو Odoo Education أو مستودع وثائق أو REST API | اختيار مصدر واحد على الأقل | لا تُطلب بيانات اعتماد ولا يُنشأ اتصال |
| 3. تحليل المخطط | زر لمحاكاة عرض كيانات وحقول نموذجية | تشغيل المحاكاة محليًا | لا يوجد introspection أو قراءة schema حقيقية |
| 4. Smart Views | اختيار قوالب مرخصة وفق نوع المصدر والتصنيف | عرض واحد مسموح على الأقل | لا تنفيذ SQL أو نشر Views |
| 5. الفهرسة | خطة ثلاث أو اثنتي عشرة وثيقة رمزية أو تجاوز الفهرسة بلا ملفات | إجراء المحاكاة محليًا | لا رفع ملفات، ولا embeddings، ولا Qdrant |
| 6. مراجعة الجاهزية | ملخص وفحوص وحالة كل مرحلة | اكتمال البنود والإقرار التجريبي | لا تفعيل أو إعداد مؤسسات حقيقي |

## تجربة المستخدم

- صفحة بالهوية المعتمدة (كحلي #0A2342، تركوازي #00A6B2، خلفية فاتحة، RTL).
- شريط خطوات واضح وتقدم مستقل يقيس المعايير التجريبية الخمسة الأولى.
- أزرار السابق/التالي، رسائل خطأ عربية، نافذة تأكيد الإكمال، وإعادة البدء مع تأكيد.
- حفظ واستعادة مسودة وصفية في `localStorage` بمفتاح `bayan-onboarding-draft-demo-v1`، مع قائمة سماح صارمة للحقول وعدم تخزين بيانات اعتماد.
- زر تنزيل **ملخص JSON تجريبي** يصرّح بأن `executedRequests: 0` و`createdDatabaseObjects: 0`.
- حماية العرض التجريبية: يحجب النموذج عن أي دور لا يملك `onboarding.run`. يجب تنفيذ التحقق الحقيقي في الخادم.

## قواعد الأمان

1. مسؤول المنصة لا يرث صلاحيات قراءة محتوى المؤسسات، ولا يرى بيانات الطلاب أو كلمات المرور أو الوثائق الحقيقية.
2. لا يتم إدخال أو تخزين معلومات اتصال أو رموز أسرار في واجهة التهيئة.
3. تصنيف قالب Smart View لا ينخفض إلى مستوى داخلي إذا كان القالب مصنفًا «مقيّدًا». القوالب غير المتاحة لا تظهر للاختيار.
4. نتائج المحاكاة ليست إثباتًا بصحة الاتصالات أو بنجاح التهيئة الإنتاجية.
5. لا يُستخدم `localStorage` للاعتماد أو لتهيئة مؤسسة فعلية؛ تحفظ فيه بيانات نموذجية وصفية فقط.
6. سيكون تطبيق عزل المستأجرين RBAC/Tenant Isolation داخل Backend وبوابة قواعد البيانات شرطًا قبل التشغيل الفعلي.

## حالات الاختبار المطلوبة

- نموذج دور `platform_admin` يمكنه فتح الشاشة؛ دور `employee` يُمنع من العرض.
- لا يمكن تجاوز المرحلة الأولى دون مؤسسة مؤهلة أو إدخال صالح.
- لا يمكن تجاوز اختيار مصدر فارغ.
- لا يمكن تجاوز تحليل المخطط أو الفهرسة دون الضغط على زر المحاكاة.
- يمنع اختيار قالب غير متاح لنوع المصدر أو لمستوى التصنيف.
- لا يمكن الإنهاء من دون مراجعة جميع الخطوات وإقرار المستخدم.
- لا يتم تنفيذ `fetch` أو `axios` أو اتصالات قواعد بيانات في هذه الشاشة.
- المسودة المعاد تحميلها لا تستعيد الإقرار السابق ولا الحقول غير المسموح بها.
- تعمل الواجهة بتخطيط متجاوب عند عرض 390 و768 و1280 بكسل.

## عقود Backend مستقبلية مقترحة — غير منفّذة

| الطلب | مسار توضيحي | الهدف |
|---|---|---|
| POST | `/api/v1/platform/onboarding` | إنشاء عملية تهيئة مع مراجعة هوية المؤسسة والقيود |
| GET | `/api/v1/platform/onboarding/{job_id}` | قراءة حالة تشغيل مصرح بها دون معلومات سرية |
| POST | `/api/v1/platform/onboarding/{job_id}/validate` | تحقّق آمن من إعدادات المصادر في الخادم |
| POST | `/api/v1/platform/onboarding/{job_id}/confirm` | اعتماد مخطط الإجراءات وبدء مهام مراجعَة ومُدقَّقة |
| GET | `/api/v1/platform/onboarding/{job_id}/events` | أحداث تقدم معالجة مناسبة للعرض، دون أسرار |

**تنبيه:** هذه واجهات REST **مقترحة فقط**؛ لا تُعد موجودة في الشفرة الحالية أو عقودًا مثبتة.
