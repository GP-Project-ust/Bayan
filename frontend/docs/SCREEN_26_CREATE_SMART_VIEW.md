# الشاشة 26 — إنشاء عرض ذكي جديد (Smart View Draft Builder)

## الغاية
واجهة Next.js عربية RTL لإنشاء **مسودة تعريفية محلية** لعرض ذكي (Smart View)، في نطاق UC-05 وFR-09/FR-10 وفق مخطط النظام. لا تُنشئ SQL View، ولا تطّلع على بيانات فعلية، ولا تنشر المسودة على أي خادم.

- المسار: `/admin/smart-views/new`.
- الصفحة المرتبطة: `/admin/smart-views`؛ تظهر المسودات المنشأة هناك وتقبل الحذف المحلي فقط.
- الدور التجريبي المسموح: مسؤول تقنية المعلومات `it_admin`، عبر `smartviews.manage`؛ وليست المصادقة أو الصلاحية الفعلية.

## خطوات المعالج

| الخطوة | المدخلات | التحقق | النتيجة |
|---|---|---|---|
| 1. التعريف والمصدر | اسم، وصف، مصدر تدريبي | اسم 5–70، وصف 12–220، عدم التكرار، مصدر غير محظور ذو مخطط تمثيلي | مصدر مختار |
| 2. الجداول والحقول | جدول واحد و1–8 حقول | حقول من المخطط الثابت، لا تكرار، استبعاد الحقول `restricted` و`blocked` | قائمة حقول مصرح بها في العينة |
| 3. التصنيف والتصفية | مستوى الوصول، الجمهور، النطاق، شرط رمزي | تصنيف العرض ≥ المصدر والحقول؛ التصفية فقط على حقل مختار، والعامل والقيمة من قوائم ثابتة | تعريف مقيد |
| 4. المعاينة | JSON وصيغة SQL تخطيطية عند ملاءمة المصدر | إقرار صريح بأن المعاينة غير منشورة ولا منفذة | معاينة للقراءة فقط |
| 5. الحفظ | مراجعة نهائية وتأكيد | تحقق شامل، حد 12 مسودة، ضمان نجاح localStorage | مسودة محلية جديدة |

## التعامل مع البيانات والأمان

1. الأمثلة مأخوذة **حصريًا من مخططات تدريبية** سبق تعريفها في `lib/data-sources/details.ts`. لا يُجرى استكشاف مخططات حقيقي.
2. المصدر المحظور أو المعطل أو المضاف محليًا بلا مخطط ثابت **غير مؤهل**؛ لا تظهر مصادر جديدة على أنها موصولة فعليًا.
3. الحقول من فئتَي `public` و`masked` فقط. حقول `restricted` و`blocked` لا تدخل قائمة الاختيار. **حتى الحقول المسموحة تدريبيًا ليست موافقة إنتاجية**.
4. الحد الأدنى لتصنيف العرض مستمد من المصدر والحقول، ولا يمكن للمستخدم تقليله.
5. لا حقل نص حر لحقن SQL؛ المعاينة تستخدم أسماء حقول وجداول من قوائم مسموحة، وقيمة تصفية مُعلّمة `:filter_value`، ولا يُنفّذ أي SQL أو اتصال شبكة.
6. لا تُحفظ كلمات مرور أو Tokens، ولا بيانات جداول، ولا معلومات حسابات حقيقية. يحتفظ `localStorage` ببيانات وصفية محددة (`bayan.demo.smartviews.drafts.v1`). **يجب عدم إدخال أسماء أو وصف حقيقيين حساسين في النموذج التجريبي**.
7. يقوم استرداد المسودات بتصفية المعرّفات والمصادر والجدول والحقول والتصنيف والحالة والبيانات الوصفية وفق قوائم مسموحة؛ لا تُستعاد مسودات غير صالحة.
8. تعتمد حماية الخادم المستقبلية على مصادقة FastAPI، وعزل المستأجرين، وفحص التصنيف وحقوق القراءة لكل حقل، وتدقيق SQL، وتسجيل الأثر. لا يحل RBAC في الواجهة محلها.

## ملفات الشفرة

- `app/admin/smart-views/new/page.tsx` — المسار والبيانات الوصفية.
- `components/smart-view-create/CreateSmartViewScreen.tsx` — المعالج، المعاينة، الحفظ، حالات الوصول.
- `components/smart-view-create/create-smart-view.css` — تصميم مستقل متجاوب مع RTL.
- `lib/smart-view-create/wizard.ts` — منطق التحقق والتصنيف وإعادة تحميل المسودات.
- `components/smart-views/SmartViewsScreen.tsx` — إظهار المسودات في القائمة وحذفها محليًا.
- `tests/contracts/create-smart-view.test.mjs` — 9 اختبارات عقود.
- `tests/e2e/create-smart-view.spec.ts` — سيناريوهات Playwright جاهزة للتشغيل.

## أوامر التجربة

```bash
npm install
npm run check:create-smart-view
npm run lint
npm run build
npm run dev
```

افتح `http://localhost:3000/admin/smart-views/new`، واختر «تعبئة مثال تدريبي»، وأكمل الخطوات، ثم افتح قائمة العروض للتحقق من ظهور المسودة.

## ما لم يكتمل

- إنشاء أو اعتماد أي PostgreSQL View أو SQL حقيقي.
- حفظ المسودات على الخادم وربطها بمؤسسة فعلية.
- تطبيق RBAC وعزل البيانات والحوكمة من Backend.
- إجراء بناء Next.js وتشغيل Playwright والمتصفح بعد تثبيت الحزم (ما لم تُوثَّق نتيجة تشغيل فعلية لاحقًا).
