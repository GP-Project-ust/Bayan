# الشاشة 37 — مراقبة الوكلاء الذكيين (AI Agents Monitoring)

- **المسار:** `/platform/agents`
- **الدور:** مسؤول المنصة (`platform_admin`) في نموذج الصلاحيات.
- **مرجع المتطلبات:** `FR-27` كما هو مدرج في `lib/screen-catalog.json` وخطة واجهات بيان.
- **التقنية:** Next.js App Router + React + TypeScript + CSS scoped.

## 1. الهدف

تقديم لوحة تشغيلية لمسؤول المنصة تعرض أدوار الوكلاء الخمسة في نظام بيان ومؤشرات مجمّعة تساعد على فهم توزيع الخطوات وحالات النجاح والفشل ومدد التنفيذ، من دون فتح محتوى مؤسسة أو مستخدم.

## 2. الوكلاء وفق وصف المشروع

| المعرّف | الاسم العربي | المسؤولية |
|---|---|---|
| `Supervisor` | المنسّق | تحليل نية السؤال وتوجيهه إلى الوكيل أو المسار الأنسب وتنسيق تدفق العمل في LangGraph. |
| `SQL` | وكيل SQL | تحويل اللغة الطبيعية إلى استعلامات بيانات عبر طبقة العروض الذكية والتعامل مع PostgreSQL ضمن الصلاحيات. |
| `RAG` | وكيل RAG | البحث الدلالي في المستندات المفهرسة وتجهيز إجابات مدعومة بالمراجع. |
| `Analyst` | المحلّل | استخراج الرؤى والاتجاهات الإحصائية من نتائج البيانات والمساعدة في اكتشاف القيم الشاذة. |
| `Reporter` | منسّق الإجابة | تنسيق مخرجات الوكلاء وإنتاج إجابات وتقارير عربية بصيغ متعددة. |

قد يوجّه `Supervisor` الطلب إلى `SQL` أو `RAG` أو مسار مركب. لا يلزم مرور كل طلب عبر الوكلاء الخمسة جميعًا؛ ويُستخدم `Analyst` و`Reporter` وفق طبيعة المهمة.

## 3. مكونات الشاشة

1. **مؤشرات عامة:** عدد الوكلاء، وعدد خطوات العينة، والخطوات الناجحة والفاشلة.
2. **مخطط المسار المعماري:** تمثيل دور المنسّق وتفرع المعالجة إلى SQL أو RAG ثم التحليل والتقرير عند الحاجة.
3. **بطاقات الوكلاء:** الاسم والمعرّف والمسؤولية والحالة التوضيحية وعدد خطوات العينة ومتوسط المدة ونسبة النجاح.
4. **البحث والتصفية:** بالاسم أو المسؤولية أو المجموعة أو حالة العينة.
5. **درج التفاصيل:** المهمة والمدخلات والمخرجات والتكاملات التصورية وتوزيع حالات الخطوات.
6. **مقارنة الأداء:** أشرطة لنسب النجاح وموجز لحالات الوكلاء.
7. **تصدير CSV:** بيانات وصفية ومؤشرات مجمعة فقط، مع حماية من CSV Formula Injection.
8. **روابط تشغيلية:** الانتقال إلى صحة الخدمات ومزودي النماذج.

## 4. مصدر الأرقام وطريقة الحساب

تُحسب المؤشرات من `lib/agent-traces/traces.ts`، وتحديدًا من مجموعة التتبعات الاصطناعية الثمانية المضمنة في المشروع. وهي لا تمثل إحصاءات إنتاجية أو نشاطًا حيًا.

- **عدد الخطوات:** عدد خطوات العينة المنسوبة إلى الوكيل.
- **عدد مسارات العينة:** عدد سجلات التتبع الاصطناعية التي يظهر فيها الوكيل.
- **نسبة النجاح:** `الخطوات الناجحة ÷ (الناجحة + الفاشلة + المرفوضة) × 100`، مع استبعاد الخطوات الجارية والمتجاوزة من المقام.
- **متوسط المدة:** متوسط مدد الخطوات التي لها مدة رقمية فقط، مع استبعاد `null`.
- **الحالة التوضيحية:** `attention` عند وجود فشل في العينة، وإلا `processing` عند وجود خطوة جارية، وإلا `ready` عند وجود خطوات، و`idle` عند عدم وجود خطوات.

القيم الحالية في العينة: 5 وكلاء، 27 خطوة، 19 ناجحة، خطوتان فاشلتان، خطوة مرفوضة واحدة، خطوة جارية واحدة، و4 خطوات متجاوزة. هذه الأرقام مشتقة آليًا من بيانات العرض، وليست قياسات حقيقية.

## 5. الصلاحيات والخصوصية

- تتطلب معاينة الشاشة `platform.manage`.
- رابط تفاصيل التتبعات المؤسسية لا يظهر إلا إذا كانت `traces.view` متاحة. الدور `platform_admin` الحالي لا يرث هذه الصلاحية، لذلك تظهر رسالة توضح أن تفاصيل تتبعات المؤسسة تبقى ضمن نطاق مسؤول تقنية المعلومات.
- لا تعرض الشاشة معرّفات المؤسسات أو المستخدمين أو نص السؤال أو محتوى الوثائق أو SQL الخام أو مفاتيح الوصول أو الاستدلال الداخلي للنموذج.
- مصفوفة الواجهة ليست حدًا أمنيًا؛ يجب تنفيذ التحقق من الهوية والصلاحيات وعزل المؤسسة في FastAPI قبل إرجاع أي بيانات حقيقية.

## 8. حدود التنفيذ والتكامل اللاحق

هذه شاشة Frontend تجريبية؛ لا تستدعي LangGraph أو FastAPI ولا تتصل بقاعدة بيانات أو مزود نموذج. عند التنفيذ الفعلي يُوصى بتوفير endpoint مجمّع على مستوى المنصة، مثل `GET /api/platform/agents/metrics`، يعيد مقاييس غير مرتبطة بمؤسسة، مع endpoint منفصل لتفاصيل التتبع المؤسسي يخضع لتفويض المؤسسة و`traces.view`. يجب أن تكون مدد التنفيذ ومعدلات النجاح محسوبة في الخادم من بيانات رصد موثوقة، مع طوابع زمنية حقيقية وسجل تدقيق.

## 9. أساس توصيف الوكلاء

تم الحفاظ على أسماء الوكلاء وأدوارهم كما وردت في ملف `main.pdf` المرفق بمشروع بيان، ولا سيما وصف معمارية الوكلاء في الفصل الثاني والشكل `2-2`، إضافة إلى وصف النظام المقترح ومتطلبات الدورة الثالثة في الفصل الثالث. لم تُقدَّم حالات العينة أو نسب النجاح على أنها واردة في ملف المشروع؛ فهي بيانات واجهة اصطناعية مشتقة من سجلات التتبع التدريبية في المستودع.
