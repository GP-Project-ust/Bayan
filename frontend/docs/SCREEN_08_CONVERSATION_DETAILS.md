# الشاشة 08 — صفحة تفاصيل المحادثة (Conversation Details)

## 1. الهدف والنطاق

تطوير واجهة مستقلة في مشروع **بيان (Bayan)** لعرض تفاصيل محادثة تجريبية كاملة على المسار `/conversations/[id]`، اعتمادًا على السجل الذي أُنشئ في الشاشة 07. تعرض الصفحة الرسائل، والأسماء، والتواريخ، والمصادر مع أرقام صفحاتها، واستعلام SQL عند وجوده وبحسب الدور التجريبي، ومخططًا تشغيليًا توضيحيًا للوكلاء.

**الحدّ الصارم:** جميع البيانات محاكاة في Frontend. لا تتصل هذه الشاشة بقاعدة بيانات الجامعة، ولا تشغّل LangGraph أو SQL أو Qdrant أو RAG، ولا تقرأ محادثات مستخدمين حقيقيين.

## 2. الهوية البصرية

- الألوان الأساسية: الكحلي `#0A2342` والتركوازي `#00A6B2` والخلفية `#F5F9FD`.
- لغة عربية كاملة واتجاه RTL؛ خط Cairo مع بدائل محلية.
- تستخدم `ChatLayout` وشريط بيان الجانبي المعتمد، مع CSS محصور بالفئات `bcd-`.
- لم تتغير الملفات المرجعية `app/globals.css` و`components/ChatView.tsx` و`components/AdminDashboard.tsx` والصورتان المعتمدتان.
- أُضيف إلى الشاشة 07 رابط مستقل «فتح الصفحة» داخل كل عنصر ورابط «فتح صفحة المحادثة الكاملة» داخل درج التفاصيل، مع الحفاظ على «عرض التفاصيل» القديم.

## 3. مناطق الشاشة

| المنطقة | وصف السلوك |
|---|---|
| رأس الصفحة والمسار | الرئيسية ← سجل المحادثات ← التفاصيل؛ عنوان ونبذة عن البيانات التجريبية |
| بطاقة المحادثة | العنوان والنوع والتاريخ وعدد الرسائل والمراجع وإجراءات المفضلة وإعادة التسمية ونسخ الرابط |
| تبويب المحادثة | عرض الرسائل باستخدام `MessageBubble`، نسخ نص المحادثة، إضافة سؤال متابعة تجريبي |
| تبويب المصادر | بطاقات `CitationCard` مع اسم المستند ورقم الصفحة ودرج يوضح أن المصدر افتراضي |
| تبويب التنفيذ | `SQLViewer` للقراءة فقط و`AgentTraceViewer` لتتبع خطوات تشغيلية توضيحية |
| الشريط الجانبي للصفحة | ملخص وإعداد دور المعاينة والتنقل والحذف |
| الحالات الاستثنائية | معرف غير معروف، محادثة محذوفة محليًا، رفض وصول للدور، تعذر التخزين أو النسخ |
| التجاوب | أحجام الهاتف والتابلت والكمبيوتر؛ تتحول الأعمدة إلى عمود واحد على الأجهزة الصغيرة |

## 4. عقد المسار واستخدامه

| مثال | المعنى |
|---|---|
| `/conversations/chat-101` | محادثة تجريبية تحتوي على استعلام SQL |
| `/conversations/chat-102` | محادثة تجريبية تتضمن مستندات وصفحات توضيحية |
| `/conversations/chat-103` | مثال لنتائج التقارير |
| `/conversations/chat-999` | معرّف غير موجود؛ تعرض الصفحة رسالة مناسبة |
| `/conversations/chat-101` بعد حذفها | حالة «المحادثة محذوفة من المعاينة» مع رابط للعودة إلى السجل |

يستمد المسار البيانات من مصفوفة الشـاشة 07 في `lib/conversations/conversations.ts`، ويطبق تعديلات الأسماء والمفضلة والحذف التي يخزنها متصفح المستخدم بالمفتاح `bayan.demo.conversations.v1`. يُفحص المعرّف على أساس قائمة ثابتة من العينات، ولا يُستخدم للوصول إلى API.

## 5. صلاحيات الواجهة (RBAC Demo)

- `chat.ask`: السماح بعرض المحادثة من الأساس.
- `citations.view`: السماح بعرض أسماء المصادر وصفحاتها في التبويب والبطاقات.
- `sql.inspect`: السماح بعرض استعلام SQL التجريبي للقراءة فقط.
- `traces.view`: السماح بمشاهدة **خطوات التشغيل التجريبية**، وليس سلسلة استدلال النموذج الداخلية.
- يتحكم `DemoRolePicker` في الدور محليًا لاختبار التفرّع. `employee` مبدئي، و`it_admin` يتيح SQL والتتبع.

**هام أمنيًا:** كون البيانات التجريبية مضمنة داخل JavaScript يعني أن إخفاء عناصر الواجهة لا يحميها من الفحص التقني. عند تنفيذ التطبيق الحقيقي يجب أن يتحقق الخادم من المصادقة، وملكية المحادثة، ووجود المستخدم في المؤسسة الصحيحة، والصلاحية لكل مصدر/استعلام/تتبع **قبل** إرسال البيانات إلى المتصفح. لا يحق لمسؤول المنصة وراثة وصول تلقائي إلى بيانات المستأجرين.

## 6. حالات التفاعل والخصوصية

- تعديل الاسم، وإضافة المفضلة، وحذف المحادثة: تُحفظ تغيرات عينات السجل فقط في `localStorage` بعد فحص البيانات.
- المتابعة: تُضاف الرسالة ونص توضيحي ثابت إلى ذاكرة React، وتختفي عند تحديث الصفحة؛ لا يوجد إرسال إلى الخادم أو سجل دائم.
- نسخ النص: ينسخ الرسائل وعنوانها مع علامة «بيانات تجريبية»؛ **لا** يشمل استعلامات SQL.
- نسخ الرابط: ينقل رابط المعاينة الحالي إلى الحافظة عند سماح المتصفح.
- المصدر: لا يوجد نص مقتبس من وثيقة حقيقية أو رابط PDF موثّق؛ يوضح الدرج ذلك صراحة.
- خطوات الوكلاء: سلسلة أحداث تشغيلية ثابتة ومختصرة (Supervisor ثم SQL/RAG/Analyst ثم Reporter)، ولا تتضمن أي استدلال داخلي أو سجلات فعلية.
- لا تُخزن كلمات مرور أو رموز جلسات أو بيانات مؤسسية حساسة.

## 7. عقود Backend المطلوبة مستقبلًا — مقترحة وغير منفذة

| الطريقة | المسار المقترح | وظيفة الخادم |
|---|---|---|
| `GET` | `/api/v1/conversations/{id}` | جلب محادثة مملوكة للمستخدم ضمن مؤسسته مع الرسائل المرخصة فقط |
| `GET` | `/api/v1/conversations/{id}/citations` | استعادة المصادر المسموح بها من RAG مع رقم الصفحة الصحيح |
| `GET` | `/api/v1/conversations/{id}/execution` | جلب ملخص SQL والأحداث التشغيلية المعتمدة بحسب الأذونات |
| `POST` | `/api/v1/conversations/{id}/messages` | متابعة الحوار مع بث SSE عند دعم الخلفية |
| `PATCH` | `/api/v1/conversations/{id}` | تحديث الاسم والمفضلة وفق سياسات المنصة |
| `DELETE` | `/api/v1/conversations/{id}` | حذف المحادثة وفق سياسة الاحتفاظ والملكية |

هذه **مسارات مقترحة** ينبغي مواءمتها مع Backend الحقيقي، وليست تأكيدًا بوجودها. يجب التعامل مع رموز 401 و403 و404 و429 و500، وأخطاء الشبكة، وعدم إظهار بيانات غير مصرح بها في جسم الاستجابة.

## 8. اختبار الشاشة

من جذر المشروع بعد تثبيت الحزم:

```bash
npm install
npm run check:conversation-detail
npm run check:conversations
npm run lint
npm run build
npm run dev
npx playwright install chromium
npm run test:e2e
```

- فحوص العقود في `tests/contracts/conversation-detail.test.mjs`: صحة المعرّفات وحالات الحذف والتسمية والمفضلة، وتكييف الرسائل والمصادر، ومسارات الوكلاء، ونسخ نص دون SQL.
- سيناريوهات Playwright في `tests/e2e/conversation-detail.spec.ts`: المسار المباشر، والتبويبات، وصلاحيات العرض، وحالات 404 التجريبية، والحذف والتنقل، وشاشة 390px.
- الفاحص `scripts/verify-conversation-detail.mjs`: سلامة ملفات الشاشة، وقراءة TypeScript نحويًا، والتأكد من عدم تغيير الصور المرجعية والواجهات القديمة.

**نتائج هذه الفحوص لا تساوي اختبار البناء أو تحققًا بصريًا شاملاً:** يلزم تشغيل `npm install`, `npm run lint`, `npm run build` وPlaywright على جهاز التطوير، ومراجعة المخرجات بصريًا، قبل اعتماد الصفحة نهائيًا.
