# بيان — دليل المرحلة الخامسة: States & RBAC

## نطاق العمل

المرحلة الخامسة من تأسيس نظام تصميم «بيان» هي **حالات الواجهة والتحكم في ظهورها حسب الدور**، بالاستناد إلى تقسيم الأدوار في الفصل الثالث (PA، وTU: مسؤول تقنية المعلومات، مدير المؤسسة، الموظف) وحالات الاستخدام UC-01 إلى UC-07. **لا تنفذ هذه الحزمة مصادقة حقيقية أو حماية Backend**؛ كل القيم في بيئة العرض هي اقتراحات هندسية لتجربة المستخدم.

## التنفيذ

- `lib/access/policy.ts`: قائمة الأدوار الأربعة ومصفوفة القدرات المقترحة، والدوال `hasPermission`, `canPreviewRoute`, `visiblePreviewRoutes`.
- `components/access/DemoAccess.tsx`: `DemoAccessProvider` و`DemoRolePicker` و`Can` و`PreviewRouteGuard` و`useDemoAccess`.
- `components/states/StatePanel.tsx`: `StatePanel`, `LoadingSkeleton`, `ErrorCodeDetail`.
- `app/design-system/states-permissions/`: واجهة تفاعلية تعرض صلاحيات الأدوار وحالات النظام وبوابات الوصول ومصفوفة الصلاحيات.
- `components/FeaturePage.tsx`: إضافة معاينة تغيّر الدور في الصفحات الفرعية وتُظهر حالة 403 محليًا عند غياب الصلاحية. لم تمس هذه الإضافة نسختي `/` و`/admin` المرجعيتين.

## الحالات الإحدى عشرة

| الحالة | الاستخدام | الإجراء |
|---|---|---|
| `idle` | جاهز لكتابة سؤال | بدء المحادثة |
| `loading` | جاري تجهيز النتيجة | منع الإرسال المكرر |
| `streaming` | استقبال رد SSE تدريجي | عرض النص الجاري |
| `success` | اكتمل الطلب | عرض النتائج |
| `empty` | لا توجد نتائج | تغيير السؤال أو النطاق |
| `invalid_input` | خطأ 400 | إرشاد إلى الحقول التي تحتاج تصحيحًا |
| `unauthenticated` | خطأ 401 | تسجيل الدخول مجددًا |
| `error` | خطأ 500 | إعادة المحاولة أو دعم فني |
| `forbidden` | خطأ 403 | إيضاح الدور المطلوب دون كشف البيانات |
| `rate_limited` | خطأ 429 | إرشاد المستخدم إلى الانتظار |
| `offline` | انقطاع اتصال | التحقق من الاتصال وإعادة المحاولة |

**قواعد العرض:** استخدام `role="alert"` لرسائل المنع/الخطأ و`role="status"` للانتظار والنجاح؛ `aria-busy` عند التحميل والبث، وتقليل الحركة عند تفعيل Reduced Motion. الرموز التقنية يجب أن تكون غير حساسة ومفصولة عن النص الموجّه للمستخدم.

## سياسة الصلاحيات في مرحلة التصميم

- **الموظف:** الأسئلة التشغيلية والبحث والمصادر واستعراض التقارير العامة حسب السياسة.
- **المدير:** وظائف الموظف + إنشاء التقارير وتصديرها والتحليلات.
- **مسؤول تقنية المعلومات بالمؤسسة:** وظائف الاستعلام الأساسية + إدارة حسابات المؤسسة والأدوار ومصادر البيانات والعروض الذكية والتدقيق والتتبع، مع عرض SQL للمصرّح له.
- **مسؤول المنصة:** تشغيل خدمات المنصة وتهيئة المؤسسات الجديدة، **من دون وراثة تلقائية لصلاحيات الاطلاع على بيانات المؤسسات**.

تتبنى محاكاة الوصول فصلًا محافظًا بين مسؤول المنصة ومسؤول المؤسسة؛ وقد تضمنت قائمة الشاشات في إصدار المخطط السابق مسؤول المنصة في بعض صفحات إدارة المؤسسة. عُدلت **محاكاة الصلاحيات فقط** لتطبيق الفصل المذكور؛ لم يتغير كتالوج الشاشات ولا الواجهتان الأصليتان.

## ما يجب تنفيذه في Backend قبل الإنتاج

1. توثيق المستخدم عبر جلسات آمنة أو رموز قصيرة العمر، والتحقق منها على كل API.
2. تحميل الدور والـ tenant_id من مصدر موثوق، وعدم قبول دور الواجهة كدليل صلاحية.
3. فحص صلاحية العملية والمسار والمستند/الجدول/السجل المطلوب، بما في ذلك سياق المؤسسة **لكل طلب**.
4. إرجاع HTTP 401 لعدم المصادقة، و403 لمنع الصلاحية، و400 للمدخلات غير السليمة، و429 لحد المعدل، و500 لأخطاء الخادم؛ مع رمز داخلي ورسالة عربية وتفاصيل تشخيصية آمنة.
5. التحقق من سياسات `Public`, `Masked`, `Restricted`, `Blacklist` عند تنفيذ الاستعلام وعرض وثائق RAG، ومنع تنفيذ استعلام SQL غير مأمون.
6. عدم إرسال بيانات محجوبة إلى العميل أصلًا، وتسجيل أحداث حساسة دون نشر الأسرار في Agent Trace أو Audit Log.
7. اختبار جميع المسارات ببيانات مستخدمين ومؤسسات مختلفة، واختبار حالات محاولة الوصول غير المصرح به.

## اختبارات المعاينة

- `npm run check:stage5` يراجع قائمة الملفات وكتالوج الشاشات وصحة صياغة TypeScript ومصفوفة الصلاحيات والحالات الحدودية.
- `npm run lint` يشغّل `tsc --noEmit` بعد تثبيت الحزم.
- `npm run build` لاختبار إنتاج Next.js بعد تثبيت الحزم.
- `npm run dev` ثم افتح `/design-system/states-permissions`، واختبر تغيير كل دور، كل حالة، فتح صفحة محجوبة ثم تغيير الدور في الصفحة نفسها، وأجهزة الهواتف.

## حدود النسخة

- لم يُضف أي اتصال حقيقي بـ FastAPI أو Odoo أو Qdrant.
- لا توجد جلسة مصادقة أو تحقق على خادم Next.js؛ فقط محاكاة Client-side.
- لا تدّعي حالات النجاح والخطأ أي نتائج فعلية؛ كلها حالات تجريبية.
- CSS المرحلتين السابقتين وصور المرجع وملفا واجهة المحادثة والإدارة الأصلية محفوظة دون تعديل.

## المرحلة السادسة التالية

التجاوب وإمكانية الوصول: تدقيق 320–1920px، والتنقل بلوحة المفاتيح، والتركيز، والتباين، ونمط Reduced Motion، واختبار RTL واللغة العربية في الجداول والنوافذ وعرض SQL.
