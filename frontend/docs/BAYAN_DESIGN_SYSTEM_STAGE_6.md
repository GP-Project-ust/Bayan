# مشروع بيان — دليل المرحلة السادسة: Responsive Design & Accessibility

**المرجع:** واجهتا المحادثة والإدارة الأصليتان، والمراحل 1–5 من نظام التصميم.  
**حالة التسليم:** تنفيذ واجهات وتعديلات CSS/React مع اختبارات تركيبية؛ **لا يُعد اختبارًا مكتملًا في المتصفح أو تقرير مطابقة WCAG**.  
**الاتجاه:** عربي RTL.  
**نطاق العمل:** العرض على الهاتف والتابلت وتحسين الوصول باستخدام لوحة المفاتيح، دون أي تعديل مقصود على النمط البصري المعتمد لسطح المكتب.

## 1. ما الذي أُنجز في الكود؟

| المجال | التطبيق | الملف |
|---|---|---|
| تخطيط متجاوب | طبقة CSS مضافة بعد CSS القديم، دون تغيير القواعد الأصلية | `styles/bayan-responsive.css` |
| القائمة الجانبية | القائمة الثابتة على الكمبيوتر تتحول إلى Drawer متحرك عند <=900px | `components/layout/AppShell.tsx` |
| زر القائمة | `aria-controls`, `aria-expanded`, تسميات عربية، مساحة لمس 44px | `components/TopBar.tsx` |
| تحكم لوحة المفاتيح | Escape + Tab focus trap + إرجاع التركيز + جعل المحتوى الخلفي inert ومنع تمريره | `components/layout/AppShell.tsx` |
| التنقل | رابط «الانتقال إلى المحتوى الرئيسي» يظهر عند التركيز | `components/layout/AppShell.tsx` |
| جداول الإدارة | منطقة تمرير بتركيز لوحة المفاتيح واسم متاح لقارئ الشاشة | `components/AdminDashboard.tsx` |
| نوافذ الإدارة والصفحات | استخدام hook موحد لضبط التركيز وEscape | `components/ui/useOverlay.ts` مع `AdminDashboard` و`FeaturePage` |
| المحادثة | `aria-live`, `aria-busy`, `aria-controls` لقسم SQL | `components/ChatView.tsx` |
| الحركة والتباين | إعدادات `prefers-reduced-motion`, `prefers-contrast` | `styles/bayan-responsive.css` |
| المعاينة | عرض الصفحات الحقيقية داخل iframe بعروض مختلفة | `/design-system/responsive` |

## 2. نقاط الانكسار Breakpoints

- **أكثر من 900px:** يبقى توزيع سطح المكتب الأصلي (الشريط الجانبي ثابت يمين الشاشة). هذا هو التصميم المرجعي المعتمد.
- **601–900px:** تعمل القائمة المتحركة وتُوزع المؤشرات والمحتويات بما يناسب الأجهزة اللوحية.
- **600px وما دون:** إعادة ترتيب الأسئلة المقترحة والتقارير والبطاقات والجداول والنماذج بصورة مناسبة للهاتف.
- **365px وما دون:** ضبط إضافي للرأس وبطاقات المؤشرات.

> نقطة الانكسار تخص طريقة العرض؛ لا تغيّر وظيفة الأزرار أو صلاحيات المستخدم.

## 3. شاشة تجربة المرحلة السادسة

مسار: `http://localhost:3000/design-system/responsive`

يمكن معاينة:
1. **الهاتف**: عرض 390px.
2. **التابلت**: عرض 768px.
3. **الكمبيوتر**: عرض 1280px.

الصفحات المدعومة في المعاينة: المحادثة `/`، ولوحة الإدارة `/admin`، والمكونات الخاصة `/design-system/bayan-components`، وخريطة الواجهات `/screens`. يمكن فتح كل صفحة في نافذة مستقلة للتأكد من سلوك التمرير والتحريك والتكبير على جهاز حقيقي.

## 4. سيناريو الاختبار اليدوي (مهم قبل الدمج)

| الحالة | الإجراء | النتيجة المرجوة |
|---|---|---|
| هاتف 390px | فتح `/` | تظهر المحادثة، وأزرار تصدير من دون تمرير أفقي للصفحة |
| هاتف 390px | فتح القائمة بالزر أعلى اليمين | Sidebar ينزلق من اليمين، والخلفية غير قابلة للتمرير |
| هاتف 390px | الضغط على Escape | تغلق القائمة ويعود التركيز لزر فتحها |
| هاتف 390px | الضغط على Tab داخل القائمة | يبقى التركيز داخل القائمة حتى إغلاقها |
| تابلت 768px | فتح `/admin` | المؤشرات والجداول والأدوات ظاهرة مع إعادة تنظيم الأعمدة |
| تابلت 768px | التنقل لجدول المستخدمين والضغط على الأسهم/التمرير | يمكن الوصول إلى بقية الأعمدة أفقيًا |
| هاتف 390px | إضافة مستخدم تجريبي | يظهر نموذج داخل نافذة قابلة للتمرير |
| أي حجم | فتح نافذة ثم Escape | تغلق وتعود لوحة المفاتيح للعنصر الذي فتحها |
| كمبيوتر 1448px | فتح `/` ثم `/admin` | يبقى التصميم السابق دون تعديل مقصود |
| تكبير 200% | فتح صفحات متعددة | النصوص والأزرار تظل قابلة للوصول (تستلزم مراجعة فعلية) |
| Reduced Motion | تفعيل الخيار من نظام التشغيل | تختفي الحركات غير الضرورية |
| قارئ الشاشة | تجربة NVDA أو VoiceOver | تسميات الأزرار والمناطق معقولة؛ يتطلب تدقيقًا يدويًا |

## 5. فحص وتشغيل محلي

```bash
npm install
npm run check:stage5
npm run check:stage6
npm run lint
npm run build
npm run dev
```

- `check:stage6`: فحص وجود الملفات والعناصر البرمجية المطلوبة وقراءة كل ملف TS/TSX باستخدام TypeScript إذا توفر.
- `npm run lint`: في هذا المشروع هو `tsc --noEmit`، وليس ESLint.
- `npm run build`: البناء الإنتاجي الكامل بعد تثبيت حزم Next.js.

## 6. حدود التنفيذ

- معاينة شاشة الهاتف في iframe ليست بديلًا عن الاختبارات في أجهزة فعلية، ولا تثبت التوافق مع WCAG 2.2 AA.
- تحسين عرض الصلاحيات لا يشكّل تحققًا أمنيًا؛ يجب فرض RBAC في Backend وقاعدة البيانات.
- قاعدة المشروع السابقة ما زالت تستخدم بيانات عرض محلية (لا توجد مصادقة أو SSE حقيقية).
- أحجام الخطوط والتباين وتفسير ترتيب التركيز تحتاج مراجعة يدوية مع أدوات الوصول عند الدمج.
- لم أغيّر الملفات `app/globals.css` أو ملفات الصور المرجعية من المرحلة الخامسة؛ جميع تعديلات العرض في ملف CSS مستقل.

## 7. المرحلة التالية

**المرحلة السابعة:** توثيق UI Kit، اختبارات القبول الآلية، لقطات مقارنة مرئية بمرجع سطح المكتب، وتوثيق حالات المكونات ومراجعة الواجهات قبل الانتقال لربط Backend.
