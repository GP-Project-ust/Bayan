# الشاشة 29: تفاصيل حدث التدقيق (Audit Event Details)

- **المسار:** `/admin/audit/details?id=AUD-DEMO-001`
- **الحالة:** نموذج واجهة Next.js، ببيانات اصطناعية فقط، غير مربوط بخادم أو سجل رسمي.
- **حالة الاستخدام:** UC-06؛ مراجعة حدث تدقيق مقيّد لمستخدم مخوّل.
- **الهوية:** RTL، الكحلي `#0A2342` والتركوازي `#00A6B2`، لا تغييرات في الواجهتين المرجعيتين.

## مكونات الشاشة

1. ترويسة وسلسلة تنقل: الإدارة ← سجل التدقيق ← تفاصيل الحدث.
2. بطاقة الحدث: الإجراء، الفئة، المورد الوصفي، المعرف، الطابع الزمني والنتيجة.
3. أربع بطاقات ملخص: الفاعل، التصنيف، التاريخ، ومعرّف التتبع.
4. أربعة تبويبات: نظرة عامة، بيانات وصفية، معرف التتبع، الخصوصية والضوابط.
5. ربط بالتنقل بين الأحداث التعليمية وبقائمة سجل التدقيق.
6. نسخ مرجع الحدث ومعرّف التتبع دون مشاركة وصف العملية في المرجع المنسوخ.
7. حالات عدم وجود معرف / المعرف غير الصحيح / المعرف غير الموجود / رفض الوصول.

## حدود البيانات والأمان

- جميع الأحداث مصدرها `lib/audit/events.ts` وعددها 18 حدثًا **تدريبيًا**.
- لا تستخدم الصفحة `fetch` أو واجهات API أو `localStorage` لتخزين أحداث أو قراءتها، ولا تسمح بتعديل أو حذف سجل التدقيق.
- يُعرض الحدث بعد فحص صلاحية `audit.view` في محاكاة الأدوار؛ **فحص React ليس حماية إنتاجية**.
- يختبر `eventDetailState` المعرف ويستبعد أي قيم غير متوقعة أو غير موجودة في القائمة المسموحة.
- معرّف التتبع تجريبي؛ لا يحتوي بيانات فعلية لخطوات LangGraph. لا يتم إنشاء تسلسل وهمي للوكلاء.
- في المنتج الفعلي يجب أن يحقق Backend هوية المستخدم ومؤسسته، وإذن المراجعة، وسياسة التنقيح وسلامة السجل والاحتفاظ به، وأن يُرجع تفاصيل محدودة مصرح بها.

## تدفق الاستخدام

سجل التدقيق ← رابط «صفحة كاملة» ← فحص الدور ← التحقق من المعرف ← استرجاع حدث التدريب ← عرض تبويبات التفاصيل ← نسخ المرجع أو العودة للسجل.

## معايير القبول

- فتح `/admin/audit/details?id=AUD-DEMO-013` يظهر مثال حدث مرفوض وإشارة للتتبع `TRACE-DEMO-0013`.
- التبديل إلى دور «مدير المؤسسة» يحجب تفاصيل الحدث والنماذج الحساسة من الواجهة.
- المعرف `AUD-DEMO-999` يظهر «الحدث غير موجود»؛ المعرف `foo` يظهر «معرّف غير صالح».
- تبويب التتبع يصرح بعدم وجود أثر حقيقي للوكلاء.
- لا توجد إجراءات تعديل أو حذف؛ وعناصر النسخ هي تفاعلات الواجهة الوحيدة التي تتعامل مع الحافظة.

## التشغيل والاختبار

```bash
npm install
npm run check:audit-details
npm run lint
npm run build
npm run dev
```

للتفاعل التلقائي: `npx playwright install chromium` ثم `npm run test:e2e`.

**حدود التحقق:** نجحت اختبارات العقود وفحوص الصياغة فقط في البيئة التي أُعدت فيها الشاشة. اختبار Next.js والبناء ومتصفح Playwright يحتاج إلى تثبيت الحزم محليًا.

## التكامل المستقبلي المقترح (غير منفذ)

`GET /api/admin/audit/events/{event_id}` مع RBAC وعزل المؤسسة، وتسجيل استعلامات التدقيق نفسها حسب سياسة المؤسسة. يمكن استخدام `trace_id` لاحقًا للانتقال إلى بيانات التتبع المتاحة للمستخدم المصرح له؛ لا يُفسَّر وجود معرّف على أنه ضمان لتوافر أثر كامل للوكلاء.
