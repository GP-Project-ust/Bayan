# دليل مسار التهيئة الذكية للمراحل 0–8

## تسلسل المراحل وبوابات التحقق

1. **المرحلة 0 — الاستلام (`intake`):** إنشاء ملف المؤسسة وتسجيل الأهداف والقطاع ثم اعتماد الاكتمال من مشغل بشري (يُرفض الفاعل الآلي مثل `ai` أو `system`).
2. **المرحلة 1 — الاتصال الآمن (`connection`):** تعريف مصدر بيانات قراءة فقط (`PostgreSQL`, `SQLite`, `MySQL`, `MariaDB`, `SQL Server`) واختبار الاتصال بكلمة مرور عابرة لا تُحفظ.
3. **المرحلة 2 — الاكتشاف الحتمي (`discovery`):** استبطان الجداول والمشاهد والأعمدة والمفاتيح وتوليد الأوصاف العربية الحتمية وبصمات SHA-256 البنيوية والدلالية عبر PR-1.
4. **المرحلة 3 — النطاقات الدلالية (`domains`):** اقتراح النطاقات (حتمياً أو عبر AI المعتمد صراحةً) والتحقق من عدم وجود مراجع وهمية (`normalize_domain_analysis`)، مع دعم النقل والدمج واعتماد المشغل.
5. **المرحلة 4 — المفاهيم العربية (`concepts`):** توليد وتعديل المفاهيم والمرادفات وتصنيف الخصوصية (`public` / `restricted` / `blacklist`) مع حماية القرارات البشرية المعتمدة والمرفوضة عند إعادة التوليد.
6. **المرحلة 5 — العلاقات (`relationships`):** التمييز الصارم بين العلاقات المعلنة (`declared`) والمقترحة بالذكاء (`ai_inferred`) واليدوية (`manual`) بما يشمل المفاتيح المركبة؛ العلاقات المرفوضة أو المعلقة لا تُنشر أبداً.
7. **المرحلة 6 — التفعيل والتسليم (`activation`):** فحص بوابات الجاهزية لجميع المراحل السابقة ثم تفعيل المؤسسة وتشغيل `SemanticKnowledgeBridge` للفهرسة في `pgvector` وإتاحة مشاهد `Catalog v2`.
8. **المرحلة 7 — مراقبة المخطط (`monitoring`):** مقارنة البصمة البنيوية لخط الأساس مع الحالة الحالية دون إطلاق انحراف وهمي عند تغيّر عدد الصفوف فقط.
9. **المرحلة 8 — مراجعة التغييرات والمزامنة (`schema`):** توليد مقترحات دلالية مقتصرة على الكائنات المتغيرة فقط، أخذ قرار المشغل البشري، أرشفة المراجع المحذوفة بأمان، وتحديث الفهرس تزايدياً مع إعادة استخدام المتجهات غير المتغيرة.
