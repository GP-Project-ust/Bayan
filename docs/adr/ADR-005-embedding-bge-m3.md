# ADR-005: نموذج التضمين bge-m3 عبر Ollama بمصنع موحد

**الحالة:** مقبول — نوفمبر 2026
**السياق:** وثيقة المشروع (FR-20) عيّنت `e5-large` للتضمين — نموذج سحابي يتطلب
مفاتيح واتصالًا خارجيًا دائمًا. مبدأ المشروع التشغيلي: كل شيء يعمل محليًا داخل
شبكة الجامعة بلا مفاتيح (`make llm` ثم Ollama)، وكل اختبارات CI تعمل بلا أي
اتصال خارجي. كما أن مهمة طبقة التهيئة وفهرسة اللوائح (Sprint 1) تحتاج مصنع
تضمين موحدًا يعادله مصنع النماذج اللغوية (ADR-002) — لا استدعاءات SDK مبعثرة.

**القرار:**
1. نموذج التضمين المعتمد **`bge-m3` عبر Ollama** — 1024 بعدًا مثل e5-large تمامًا
   (لا تغيير في الأبعاد ولا في تصميم الفهرس)، ويعمل محليًا بلا مفاتيح.
   يعاد توثيق هذا الاستبدال في فصل التقييم من التقرير: نفس الأبعاد، تشغيل محلي.
2. مصنع موحد `app/core/qdrant.py`: `get_qdrant_client()` + `get_embeddings()`
   + `ensure_collection()` — **البوابة الوحيدة** لمستودع المتجهات والتضمين في
   كل بيان، توازي `get_llm()` في ADR-002. لا يستورد أي وكيل أو خدمة عميل
   Qdrant أو SDK تضمين مباشرة.
3. مزوّد تضمين مستقل عن مزوّد النموذج اللغوي: `EMBEDDING_PROVIDER`
   (`mock` | `ollama`) + `EMBEDDING_MODEL` + `EMBEDDING_DIMENSIONS`
   + `EMBEDDING_BASE_URL` (يفرَّغ إلى `OLLAMA_BASE_URL`) — من `.env` حصرًا.
4. `mock` هو الافتراضي: متجهات حتمية من SHA-256 (نفس النص ← نفس المتجه) —
   تجعل CI وفهرسة التطوير والاختبارات تعمل بلا أي اتصال خارجي، مع بقاء
   البنية (المجموعة، القياس cosine، الحمولة، الفلترة) حقيقية تمامًا.
5. مجموعة لوائح الجامعة الموحدة: `bayan_policies` — الاسم المعتمد في كل بيان
   (الفصل الرابع §4)، وقياسها جيب التمام (cosine).

**البدائل المرفوضة:** (أ) e5-large الأصلي — سحابي؛ يكسر التشغيل المحلي بلا
مفاتيح ويفشل CI المعزول. (ب) تضمين OpenAI — مفاتيح وتكلفة واعتماد خارجي
يحرم الفريق من بيئة موحدة. (ج) متجهات عشوائية بدل mock الحتمي — تكسر قابلية
إعادة الاختبار وفهرسة idempotent.

**النتائج:** فهرسة RAG تعمل محليًا بالكامل من يوم Sprint 1؛ تبديل نموذج
التضمين من `.env` لا من الكود؛ مقارنة نماذج التضمين لاحقًا (في فصل التقييم)
تصبح تجربة إعدادات لا إعادة كتابة. صفحة الفحص `/dev/indexer` تعرض الدورة
كاملة للفريق من المتصفح.
