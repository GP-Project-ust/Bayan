# ADR-002: مصنع نماذج موحد بالأدوار + مزوّد mock افتراضي

**الحالة:** مقبول — أكتوبر 2026
**السياق:** يحتاج كل وكيل نموذجًا مضبوطًا بطبيعته (SQL بحرارة 0،
المُعِدّ بحرارة أعلى)، والفريق خمسة أعضاء بعتاد وميزانيات مختلفة.

**القرار:** بوابة واحدة `get_llm(role)` في `app/llm/provider.py` —
لا يستورد أي وكيل SDK مزوّدًا مباشرة. الأدوار الخمسة مثبتة بدرجات
حرارتها، والمزوّد من متغير بيئة واحد `LLM_PROVIDER`:
- `mock` (افتراضي): ردود حتمية بلا اتصال — كل عضو يعمل من أول يوم
- `ollama`: محلي بلا مفاتيح (Qwen 2.5)
- السحابي (openai/anthropic/gemini): تثبيت كسوي lazy — لا يُحمَّل
  من لا يحتاجه، والمفاتيح من .env حصرًا

**البدائل المرفوضة:** (أ) LiteLLM كطبقة إضافية — قيمة كبيرة عند تعدد
المزودين والميزانيات المركزية، لكنها اعتمادية إضافية فوق ما يوفره
langchain الموجود أصلًا؛ يُعاد التقييم عند الحاجة الفعلية (يُوثّق هنا).
(ب) عميل REST مباشر — بلا tool-calling ولا مخرجات منظمة ولا تكامل مع LangGraph.

**النتائج:** تبديل المزوّد = سطر واحد في .env بلا أي تغيير كود.
الثمن: ردود mock لا تحاكي تنوع الإجابات الحقيقية — مقصود لضمان
اختبارات حتمية.
