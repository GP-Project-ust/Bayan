# ADR-001: القاعدة التجريبية الموحدة بدل إلزام كل عضو برفع Odoo

**الحالة:** مقبول — أكتوبر 2026
**السياق:** خطة التنفيذ الأصلية طلبت من كل عضو رفع بيئة OpenEduCat كاملة
(استعادة 2-5 دقائق + أرشيف ضخم + تعريض منفذ يدوي + أسماء أعمدة متغيرة بين
إصدارات OpenEduCat كما وُثّق في smart_views/00_init_views.sql نفسه).

**القرار:** قاعدة PostgreSQL تجريبية موحدة (`database/university_demo/`)
تُجهَّز بأمر واحد (`make dev-db`) بأسماء جداول وأعمدة **مطابقة لجوهر
مخطط OpenEduCat** (op_student، res_partner، op_course، ...)، فتعمل فوقها
Smart Views الحالية حرفيًا، ويشترك فيها كل الفريق ببيانات اصطناعية
عربية حتمية (seed ثابت = نتائج قابلة للمقارنة بين الأجهزة).

**البدائل المرفوضة:** (أ) Odoo لكل عضو — ثقيل ومتغير بين البيئات.
(ب) SQLite — ابتعدت عن PostgreSQL الإنتاجية (الفروق في الأنواع والسلوك).

**النتائج:** بيئة كل عضو جاهزة في ثوانٍ، والاختبارات تعمل في CI،
والترقية لقاعدة Odoo حقيقية لاحقًا شبه سلسة (نفس أسماء الجداول).
الثمن: صيانة مخطط تجريبي موازٍ حتى ربط القاعدة الحقيقية (يُراجع في Sprint 4).
