# ADR-003: عقد أحداث SSE موحد لكل الواجهات

**الحالة:** مقبول — أكتوبر 2026
**السياق:** الواجهة الأمامية Next.js لم تُبنَ بعد، والفريق يحتاج اليوم
طريقة موحدة لرؤية ما يفعله كل وكيل (التوجيه، SQL، عدد الصفوف، الأخطاء).

**القرار:** عقد أحداث دستوري في `app/core/events.py`:
`meta → agent_end (لكل وكيل) → final | error`
تنتجه نقطة البث `/api/v1/chat/stream` وتستهلكه واجهة الاختبار الموحدة
`/dev/playground` (ملف HTML واحد بلا بناء)، وستستهلكه واجهة Next.js
لاحقًا — **عقد واحد، مستهلكان**.

**البدائل المرفوضة:** (أ) WebSocket — تعقيد بلا حاجة (بث باتجاه واحد).
(ب) استجابة JSON واحدة (غير مبثوثة) — تخفي التقدم وتؤخر الإجابة الظاهرة.

**النتائج:** كل عضو يختبر السلسلة كاملة من متصفحه دون بناء الواجهة
ولا curl، والواجهة النهائية ترث عقدًا مجربًا. الأحداث المستقبلية
(agent_start/token/clarification) محجوزة في العقد لتوسيعه دون كسره.

**تحديث (نوفمبر 2026) — جدول النتائج في الحدث الختامي:** الحدث `final`
يحمل حقلًا **اختياريًا** `table` من النوع `TablePayload` المعرف في
`app/schemas/chat.py` (`columns` / `rows` / `truncated`) — يوصل جدول نتائج
وكيل SQL إلى الواجهات للعرض مباشرة بدل نص الإجابة وحده. النوع مشترك بين
حدث البث واستجابة `ChatResponse` (عقد واحد، مستهلكان)، والحقل اختياري
فلا يكسر أي متلقٍّ قديم يتجاهله. سقف عرض الجدول 50 صفًا (سقف عرض فقط،
مستقل عن سقف تنفيذ الاستعلام الذي يملكه وكيل SQL) وعلم `truncated`
يعكس القطع (تنفيذًا أو عرضًا).
