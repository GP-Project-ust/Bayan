# تصميم الوكلاء الخمسة — بيان

> الترجمة التنفيذية لفصل المعمارية في وثيقة التخرج. كل وكيل = ملف واحد
> في `backend/app/agents/` + توثيق هنا. تعديل المسؤوليات يتطلب تحديث هذا الملف أولاً.

## الحالة المشتركة (`state.py`)

الوكلاء لا تتحدث فيما بينها مباشرة — بل تقرأ وتكتب في **حالة واحدة مشتركة** يديرها LangGraph:

| الحقل | يكتبه | معناه |
|-------|-------|-------|
| `question` | نقطة الدخول | السؤال العربي بعد التطبيع |
| `conversation_id` | نقطة الدخول | لربط ذاكرة المحادثة |
| `route` | الـ Supervisor | قرار المسار التالي |
| `sql_query` | وكيل SQL | الاستعلام المولَّد |
| `query_results` | وكيل SQL | صفوف النتائج النهائية |
| `rag_context` | وكيل RAG | المقاطع المسترجعة بالتقييم |
| `answer` | المُعِدّ | الإجابة النهائية |
| `agent_trace` | الجميع | أثر التنفيذ — للواجهة والقياس والتصحيح |
| `error` | الجميع | للإصلاح الذاتي والمقاصة |

## الوكلاء

### 1) الـ Supervisor — الموجّه

- **المدخل**: السؤال + سياق المحادثة الأخير
- **المخرج**: قرار مسار (sql / rag / سلسلة مركّبة / استيضاح)
- **قواعد التوجيه**:
  - أرقام، إحصاءات، "كم"، "أي"، "قائمة" → **sql_agent**
  - لوائح، شروط، "هل يجوز"، "ما نظام" → **rag_agent**
  - "قارن"، "اتجاه"، "لماذا" → **sql ثم analyst**
  - طلب تقرير/تصدير → **سلسلة كاملة تنتهي بالمُعِدّ**
  - ضمائر غامضة بلا مرجع ("الأول؟") → **سؤال استيضاح** للمستخدم
- **البناء**: Sprint 3 (حالياً توجيه ثابت إلى SQL للشريحة الرأسية الأولى)

### 2) وكيل SQL — قلب المشروع

- **المدخل**: السؤال + كتالوج Smart Views (جداول وأعمدة بوصف عربي)
- **المخرج**: `sql_query` + `query_results`
- **السلسلة الداخلية** (Sprint 1):
  1. مطابقة المفاهيم: مسرد يربط "المتخرجين" بمفهوم ` graduation_status = 'passed'`
  2. توليد SQL بـ LLM فوق المشاهد فقط — الـ prompt يتضمن الكتالوج وأمثلة قليلة (few-shot)
  3. تحقق AST: `SELECT` فقط؛ يُرفض أي شيء آخر مهما كان السياق
  4. تنفيذ بمستخدم قراءة فقط + مهلة 5 ثوانٍ + حد 1000 صف
  5. عند خطأ: إعادة التوليد مع رسالة الخطأ (حتى 3 محاولات) ثم اعتذار واضح
- **ممنوعات**: جداول Odoo الخام، DDL/DML، أعمدة بلا وصف في الكتالوج

### 3) وكيل RAG — المعرفة المؤسسية

- **المدخل**: السؤال
- **المخرج**: `rag_context` (مقاطع موثّقة بالمصدر) + إجابة أولية
- **السلوك** (Sprint 2):
  - بحث متجهي في Qdrant (مجموعة `bayan_policies`)
  - الإجابة **بالاستشهاد فقط**: اسم اللائح + المادة + النص
  - إن لم توجد صلة كافية: يقول "لم أجد ذلك في اللوائح المتاحة" — **بلا اختراع**
- **مصدر المعرفة**: لوائح الجامعة، سياسات القبول والرسوم، خطط البرامج، دليل الطالب

### 4) المحلل — من أرقام إلى رؤى

- **المدخل**: `query_results` + السؤال الأصلي
- **المخرج**: قراءة تحليلية + مواصفة رسم (النوع والمحاور والعنوان)
- **قواعد اختيار الرسم** (Sprint 3):
  - سلسلة زمنية → خطي | فئات قليلة → شريطي | نسب من كل → دائري | علاقة → مبعثر
  - الأرقام تُعرض بأرقام عربية مشرقية مع فصل الآلاف
- **ممنوع**: اختراع بيانات غير موجودة في النتائج

### 5) المُعِدّ — الصوت النهائي لبيان

- **المدخل**: كل ما أنتجه الآخرون
- **المخرج**: `answer` نهائي: جملة مباشرة + جدول مرتب + رسم (اختياري) + مصادر (إن وُجدت)
- **قواعد الأسلوب** (Sprint 3):
  - عربية سليمة موجزة — يبدأ بالجواب ثم التفصيل
  - "لا أعرف" الواضحة أفضل من جواب مرتجل
  - توحيد التواريخ والعملة (ريال يمني) والأرقام

## أثر التنفيذ (`agent_trace`)

كل عقدة تضيف `{"agent": ..., "note": ...}` — يُستخدم في:
1. **الواجهة**: عرض شريط "يفكر الآن..." أثناء التنفيذ
2. **القياس**: تحليل أي وكيل يبطئ السلسلة (هدف p95 ≤ 3 ثوانٍ)
3. **التصحيح**: تتبع أين انهار المسار عند فشل سؤال من Golden Dataset
